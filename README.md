# VULN-AUDIT · 项目源码目标审计工作台

这是一个面向受控环境的源码白盒审计工具：**上传完整项目 ZIP → 定义审计目标与验收条件 → 主 Planner 借项目图与全量只读工具了解项目 → 建立项目级任务图 → 多 worker 审计 → 导出可复核结果**。

上传的项目整包就是审计范围，不分语言、没有勾选步骤。PHP 用 tree-sitter 建语法索引，其它语言的文本文件按纯文本行索引并可读可搜、可作证据；二进制文件只登记不可读。第三方依赖与生成目录同样进入快照，是否值得读由 Planner 按目标判断，而不是由上传者在看不到代码时预先决定。

本工具只做**源码审计**：仓库里不附带任何靶场、示例应用或被测源码包，审计目标由使用者自行提供 ZIP，POC 也要在使用者自备的授权环境中验证（见「[POC 与人工验证](#poc-与人工验证)」）。主流程不依赖预设 Prompt，也不限定固定漏洞类别。目标可以是漏洞路径、鉴权规则、敏感配置、危险依赖、路由覆盖、数据流或任意能由源码证据验证的事实。每次运行都会冻结源码快照、目标、预算和项目图；主 Planner 根据项目图、每回合的**本轮态势**（前沿任务、全部已结算方向与已有结论、覆盖统计、已固定调查）与 worker 反馈动态维护跨文件任务图，而不是把每个文件或切片直接派给 agent。Planner 回合、侦察简报、覆盖统计、固定调查、任务依赖、模型代码动作、工具调用、源码引用、worker 尝试和审计依据摘要都会持久化，刷新页面或重启服务后仍可回放。运行可以在回合边界**暂停**并原样**继续**：暂停保留前沿与回合号，不放弃任何已完成的工作。

模型的内部思维链不会被保存或展示。界面中的“审计依据摘要”是模型产出的、受源码行号约束的结论说明，结合工具轨迹与证据引用供人工复核。

## 快速开始

### 本地开发（一键启动）

```bash
cd vuln-audit              # 你克隆下来的仓库目录
cp .env.example .env       # 配置 LLM_MODEL / LLM_BASE_URL / LLM_API_KEY
./scripts/start.sh
```

脚本会同步 Python 与 Node 依赖，并启动：

- 前端：<http://127.0.0.1:5173>
- 后端 API：<http://127.0.0.1:8899>

按 `Ctrl+C` 会同时停止两个进程，日志保存在 `.run/backend.log` 与 `.run/frontend.log`。依赖已安装时可使用 `./scripts/start.sh --skip-install`；端口冲突时可使用 `AUDIT_PORT=8900 WEB_PORT=5174 ./scripts/start.sh`。

也可以分别启动：

```bash
# 终端 1
cd backend
uv sync
uv run uvicorn audit.app:app --host 127.0.0.1 --port 8899

# 终端 2
cd frontend
npm install
VITE_API_TARGET=http://127.0.0.1:8899 npm run dev
```

### Docker Compose

Compose 只启动通用审计应用，不挂载示例源码，也不带靶机：

```bash
cp .env.example .env
# 填写 LLM_MODEL / LLM_BASE_URL / LLM_API_KEY
docker compose up --build
```

审计应用位于 <http://127.0.0.1:8899>。若端口已占用，可使用 `AUDIT_PORT=8900 docker compose up --build`。

### 环境变量

| 变量 | 说明 |
| --- | --- |
| `LLM_MODEL` | 启动时生成或刷新只读环境变量档案的模型标识 |
| `LLM_BASE_URL` | 启动时生成或刷新只读环境变量档案的 OpenAI 兼容 API 根地址 |
| `LLM_API_KEY` | 仅由服务端读取，供只读环境变量档案使用 |
| `LLM_THINKING` | 默认 `disabled`；不采集或展示模型隐藏推理内容 |
| `AUDIT_DATA_DIR` | 数据目录，默认 `./data`（`audit.db`、不可变快照、证据及本地模型凭据密钥文件） |
| `AUDIT_PORT` / `WEB_PORT` | 本地一键启动或 Compose 的监听端口 |

`AUDIT_MODEL` / `AUDIT_BASE_URL` / `AUDIT_API_KEY` 和 `OPENAI_*` 也可作为兼容别名。

### 多厂商模型档案

服务启动时，环境变量会形成一个只读的初始档案；服务重启后会按当前环境变量刷新该档案。它可以被选为当前连接，但不能在界面中编辑或删除。配置页和接口仅展示去除 URL 用户信息、查询参数和片段后的 Base URL；环境变量中为兼容服务保留的原始连接地址只在服务进程内使用。

在“设置”中可新建多个独立档案。每个档案分别保存易识别的名称、模型标识、Base URL 和 API Key，因此不同厂商或端点不会共用连接信息。编辑已保存的档案时，API Key 留空表示保留原值；明确提交空值则清除该档案的已保存密钥。选择档案后，后续新建的审计会使用该档案。

界面提交的 API Key 会加密后写入 `AUDIT_DATA_DIR/audit.db`；用于解密的本地密钥文件为 `AUDIT_DATA_DIR/.model-config.key`。已提交的 API Key 不会在后续响应中返回浏览器，也不会写入审计报告。编辑档案时留空会保留原密钥；勾选“清除已保存的 API Key”才会移除它。备份、迁移或恢复数据目录时，必须一并保留 `audit.db` 和 `.model-config.key`；只保留数据库将无法恢复已保存档案的密钥。

存在 `pending` 或 `running` 状态的审计时，不能新建、编辑、切换或删除模型档案。请等待审计结束或取消后再调整档案，保证一次审计期间使用的模型连接保持不变。每个新审计还会冻结档案 ID、模型标识和公开 Base URL，便于在运行详情、事件和导出结果中追溯所用连接而不保存密钥。

## 使用流程

1. 在聊天输入区点击“添加源码”或拖入完整项目 ZIP（最大 64 MiB），也可以通过文件夹按钮复用已有快照。导入器保留原始字节和哈希，并把整包冻结成不可变快照：PHP 文件（`.php`、`.php3`–`.php8`、`.phps`、`.inc`、`.phtml`，以及带 PHP 开始标记的无扩展名或框架专用文件）另建 tree-sitter 语法索引，其它语言的文本文件按纯文本行索引，二进制文件只登记大小。路径穿越、符号链接、加密条目和超限归档仍会被拒绝；超出容量预算的单个条目按确定顺序跳过，并在快照摘要里列出 `warnings` 与 `skipped_files`。
2. 快照中的所有可读文本文件都属于审计范围，无需勾选。点击输入区“快照”查看文本 / 二进制 / 依赖树文件数、语言分布、文件清单及跳过的条目。
3. 在同一输入卡内填写“审计任务”和“验收目标”（各 8–2000 字符）。例如：
   - “追踪上传入口到文件写入操作，确认是否存在未经路径规范化的可达写入路径。”
   - “列出所有无需认证即可访问的管理路由，并给出路由定义与中间件证据。”
   - “确认会话 cookie 的 `Secure`、`HttpOnly` 和 `SameSite` 配置来源。”
4. 在“高级执行设置”调整每个动态任务的最大尝试、全局 worker 尝试上限、Planner 回合上限、并发 worker 数，以及是否要求 POC。预算默认采用服务端的每回合设置，源码事实、配置或架构目标默认不要求 POC。
5. 点击发送箭头或使用 `Ctrl / ⌘ + Enter` 开始审计。主 Planner 首轮获得紧凑的项目结构概览（模块、静态 include 图、高置信入口、引导文件与未解析关系统计）；它的工具是**全量只读**的——可以自己读源码行、检索文本、看目录树与符号大纲，也可以调用内置侦察子 agent 做一次结构侦察，拿到布局、入口候选、数据存储、安全边界与首批阅读目标。**这些读记录都只是导航线索，不是证据**：证据永远只来自 worker 实际读过的源码行。此后每回合它还会拿到宿主预取的**本轮态势**（`ready`/`running` 的前沿任务、全部已结算方向与已有结论、覆盖统计、已固定调查），据此派发尚未被读过的相关区域，而不是重复派发或过早收束；前沿非空时允许一轮派出 0 个任务。同一个调查话题只会真的执行一次，结果固定在库里，之后直接复用。高置信入口与未解析静态根分开记录；后者不会被当成路由或作为 worker 的默认起点。worker 通过原子租约领取已就绪任务，并从多个源码窗口开始审计；其结果会成为下一轮 Planner 的输入。依赖任务会把已持久化的结论摘要交接给后续 worker；worker 还可检索其他 worker 的受限工具轨迹作为线索，但仍必须自行读取源码才能引用为证据。固定 SQL/XSS/命令执行启发式不会用于目标任务。
6. 聊天流内按阶段查看 Planner、worker、侦察、代码动作和工具链；参数、保存的代码与日志、返回预览可展开和复制。通过“审计详情”查看项目与任务图、覆盖统计与固定调查、发现与复核、完整报告，下载 Markdown、JSON 和证据包。源码按需展开后加载。运行中可暂停并原样继续，也可取消。

每次审计对应一段会话，侧栏可搜索历史记录；“基于此任务新建”复用快照、目标和预算并创建独立运行。默认深色主题，可在侧栏底部切换浅色并保存偏好。品牌标题采用本地 CSS 字效，无远程字体依赖；布局与交互参考 AnythingLLM，许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

一个动态任务只能报告 `achieved`、`continue`、`no_evidence` 或 `blocked`。单个 worker 的“未发现”不会结束整个审计。只有 Planner 已穷尽已知证据方向、所有动态任务已结算、且不存在上下文或执行受阻项时，宿主才会接受“不可达”；共享尝试或 Planner 回合耗尽一律保留为“未决”。Planner 可以更正自己先前的结论：把一条已结算任务重新打开重跑（旧尝试记录全部保留，新结论以新版本写入），或撤回/标为重复一条尚未被人工裁决的结论；**人工已确认或排除的结论不可被改写**，只会记为“存疑”。撤回不等于删除——行、证据、历史版本与复核记录都留在报告里，单独成区。

## 审计结果与执行详情

每项目标任务保存：

- 不可变 ZIP 哈希、整包快照范围、任务目标、验收条件、预算和冻结项目图；
- 每个 Planner 回合的依据摘要、任务图版本、动态任务、依赖和更新记录；
- 每回合的覆盖统计（已读文件、覆盖率、未读模块）、**本轮态势**（前沿与已结算方向、已有结论、已固定调查）与侦察子 agent 的项目简报，以及侦察失败或被跳过的原因；
- 每个 worker 的动态任务领取记录、尝试、用量、已读源码行号、结构化结论和错误；
- 依赖任务的摘要交接，以及可检索的受限同行工具轨迹和依据摘要；
- 每个阶段的每次模型代码动作：被执行的代码、它 `print` 出来的日志、是否以终局结束、解释器错误与当时的用量（代码是动作，不是隐藏推理，所以照工具调用一样入库存档；代码块之外的散文不保存）；
- 每次只读工具调用的参数、状态、受限预览与关联调用 ID；
- 模型生成的审计依据摘要、缺失上下文和下一步建议；
- 经过源码边界与已读范围校验的发现、可选 POC，以及 POC 验证或源码人工复核记录；
- 每条结论的三个独立状态：引用是否核实（`validation_state`）、人工是否复现（`verdict`）、本次运行是否仍主张它（`disposition`），以及它的版本号、历史版本与派生来源。

工具与结果先落 SQLite，再经 SSE 推送。因此实时页面只是视图，数据库事件才是审计记录的来源。执行轨迹展示工具调用和模型给出的源码依据摘要，不展示或持久化提供商 thinking delta、完整隐藏推理或密钥。

## POC 与人工验证

本工具**只做源码审计**：它不提供、不部署、也不附带任何靶场或被测应用，仓库里没有可供审计的目标源码，也没有把目标跑起来的 Compose profile 或脚本。审计目标由使用者自己提供 ZIP，发现里的 POC 也必须由使用者自己在**已获授权的环境**中验证：

1. 按目标的真实版本与部署方式，自行搭建一套可复现的运行环境；
2. 把 POC 按实际地址、参数与前置状态适配后运行——脚本原样跑不通时先做适配再运行，**适配内容照实记录**，而不是直接判为排除；
3. 回填执行状态、环境说明、正常/攻击两组对照观测与附件；只有经由源码行号校验的结论才能被确认。

也就是说，POC 只是模型产出的静态审计工件，**本工具不代跑**：它不执行上传快照里的任何代码，也不向目标发起任何网络请求。历史实验留下的记录与脚本（固定漏洞实验、Prompt 轮次等）仅作为兼容数据保留，不会出现在默认工作台流程中。

## 设计边界

- 审计只读取上传快照中的源码：**不执行上传快照里的任何代码，也不执行 POC**，不发起外部网络请求。被执行的只有**模型自己写出的代码**，而且它只能做一件事——调用宿主的只读工具读这个快照。这段代码跑在进程内的受限解释器里：不能 import 任何能碰文件、网络或进程的模块（`os`、`sys`、`subprocess`、`socket`、`pathlib`、`io` 等都在禁用清单里，连名字都取不到），禁用 `eval`/`exec`/`compile` 与 dunder 属性，并有操作数、循环与打印上限；所有真实读取都必须经由宿主工具，照旧受范围校验、pin、去重、读账本与工具预算约束。
- 这个解释器**不是安全沙箱**——这是 smolagents 官方对自己 `LocalPythonExecutor` 的定性（"is not a security sandbox: for isolated execution of untrusted code, use a remote executor"），我们照抄在此而不假装相反。它挡住的是模型跑偏的代码，不是把「不可信的代码」当作威胁模型：本工具执行的从来只是模型的代码，用户的代码只被当作只读数据。要执行真正的不可信代码（例如自动验证 POC），需要换成远程隔离执行器，这不在本工具的范围内。
- tree-sitter 只用于建立 PHP 语法索引、项目图和稳定源码窗口；其它语言按纯文本行索引，不做跨语言符号解析，因此这不是完整的跨项目污点分析。动态加载、运行时配置和缺失依赖会作为未决上下文记录。
- 侦察子 agent 的简报和每回合的覆盖统计都是宿主产出的导航线索，不是 finding 证据：引用其中的任何路径，仍必须由 worker 读取原始源码行并通过校验。
- POC 是模型产生的静态审计工件，必须由人工在授权环境中验证；带 POC 的确认与排除保留执行状态、环境、对照观测和附件。没有 POC 的源码结论通过书面人工复核确认或驳回，且只有通过源码证据校验的结论能够被确认。
- 本仓库**不提供靶场**，也不代为搭建或运行目标：源码审计与 POC 验证是使用者在自备授权环境里完成的两件事，本工具只产出前者所需的证据与工件。
- 早期固定漏洞实验留下的记录与脚本是历史兼容层，不用于衡量任意上传项目的覆盖率或召回率。
