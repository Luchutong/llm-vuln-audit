# PHP 认证、授权与对象归属

检查顺序：

1. 确认操作前是否建立了会话身份，以及会话来自服务端状态还是客户端可伪造字段。
2. 对每个敏感操作核对角色或权限判断；只检查“已登录”不等于检查了授权。
3. 核对对象归属：查询条件是否包含当前用户、组织或租户，而不是只按对象 ID 读取或修改。
4. 检查批量赋值：请求字段是否被直接展开进更新语句，导致 `role`、`balance`、`owner_id` 等敏感列可写。
5. 检查状态变更后的副作用：余额、库存、订单状态、令牌是否可重复使用。

常见误判：

- 页面隐藏了按钮或字段，但服务端仍接受提交。
- 只在前端校验角色，后端接口没有同等检查。
- 角色判断使用了弱类型比较，类型转换后可绕过。
- 管理接口路径需要登录，但任何登录用户都可访问。

检查时写清攻击前身份、对象归属与必须满足的前提；不同身份下成立的条件可能不同。
