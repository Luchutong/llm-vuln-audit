# PHP 输入到危险操作

检查顺序：

1. 找到请求输入：`$_GET`、`$_POST`、`$_REQUEST`、`$_COOKIE`、上传文件、请求头或 JSON 解码结果。
2. 沿赋值、函数参数、数组元素和对象属性追到真正执行的位置，而不是只看到入口变量就下结论。
3. 识别操作类型：SQL 拼接、命令执行、文件包含或写入、模板渲染、反序列化、外部请求。
4. 核对中间防护：参数化查询、类型约束、白名单映射、路径规范化、转义函数及其上下文。
5. 若防护只覆盖部分分支，指出绕过条件与需要的前提；不要把“存在过滤函数”当成安全结论。

常见误判：

- 入口变量只被记录或比较，没有进入危险操作。
- 查询使用占位符，但表名或排序字段仍由输入拼接。
- 文件路径做了前缀检查，却可被 `..`、符号链接或空字节绕过。
- 命令执行前只过滤了少量字符，仍可通过参数分隔符或环境变量注入。

知识提示只说明检查方法，不能替代当前源码行号证据。
