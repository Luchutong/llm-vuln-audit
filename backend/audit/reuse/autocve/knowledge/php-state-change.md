# PHP 状态变更与业务副作用

检查顺序：

1. 列出写操作：用户资料、余额、库存、订单、积分、令牌、文件系统。
2. 核对写操作的字段来源与允许集合，确认服务端是否只接受业务允许的字段。
3. 检查前置状态校验：余额是否足够、库存是否为正、订单是否属于当前阶段、优惠券是否未使用。
4. 检查并发与重放：同一请求重复提交、并发提交或丢失响应后重试是否会造成多次扣减。
5. 检查跨用户或跨租户引用：写入的对象 ID 是否由服务端根据当前身份解析。

报告应区分“已观测到的状态改变”和“仅从源码推断的潜在影响”。未执行验证的推断必须标注为静态支持。

知识提示只说明检查方法，不能替代当前源码行号证据。
