## 二、实验代码版本（`code.commit = unavailable` 的说明）

### 2.1 为什么是 unavailable

虚拟机上的项目副本是**目录复制**（无 `.git` 元数据），实验运行器读取 git commit 失败后按设计写入 `unavailable`——不是隐藏版本信息。

### 2.2 代码已被完全锁定（两重指纹）

1. **运行器自带的逐文件指纹**：`manifest.code.files` 记录了 `backend/audit` 全部 **83 个代码文件的 SHA-256**。与当次运行副本复核比对：**83/83 全部匹配**。

## 三、预算参数与汇总使用量的统计口径

### 3.1 字段语义（依据 `backend/audit` 代码）

`full_comparison.py` 第 837 行生成的报告原文即注明：**「每次 Agent 执行预算：{responses 24, tools 96, seconds 720}；每试次共享预算：{responses 256, tools 2048, seconds 720}」**。即：

| 字段 | 值 | 语义 |
| --- | --- | --- |
| `budgets` | 24 / 96 / 720 | **每个 Agent（Worker）**的执行预算：响应轮数 / 工具调用 / 秒数 |
| `run_limits` | 256 / 2048 / 720 | **每个试次（一次 run）**的整体上限，由 Planner + 多个 Worker + 终审**共享** |

因此：

- **`requests`（514）不能与 `24 × 9 = 216` 直接比较**。`usage.requests` 统计的是**发往模型供应商的 HTTP 请求数**，其中包含三类**不额外消耗 responses 配额**的调用：① 输出达到 `worker_max_tokens=4096`（`finish_reason=length`）时的**续写**请求（`codemodel.py:631`）；② 历史摘要请求（`codemodel.py:599-614`）；③ 瞬时错误重试（`agent_policy.transient_retries=3`）。单试次 `requests` 为 42–67，属正常口径。
- **`tool_calls`（777）按整次 run 统计**：单试次 59–109，全部低于 run 级上限 2048；Agent 级 96 的配额由执行守卫在 Worker 内部强制，不体现在 run 汇总里。
- **tokens**：`input_tokens.known_attempts = 2/9`（7 个试次 `token_usage_complete=false`），886.6 万为**已知下限**（总览 README §4 已如实标注，报告不得写成精确总量）。
- **时长**：`audit_elapsed` 合计 4554.5 秒 ≤ 9 × 720 = 6480 秒；`wall_elapsed` 4571.6 秒（76 分 12 秒）含试次间清理开销，两者口径不同。
