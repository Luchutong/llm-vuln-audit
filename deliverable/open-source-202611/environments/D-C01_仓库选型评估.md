## 1. 评估背景与目标

本项目需要在 Lab30 自研靶场之外，选取一个**真实、可本地部署、可离线复现**的开源 Web 应用作为 LLM 辅助漏洞挖掘的审计靶标。任务清单在 S-C04 中已明确标注 **phpMyFAQ 优先**，候选范围固定为以下三个 PHP 应用：

1. **phpMyFAQ**——开源 FAQ / 知识库系统；
2. **osTicket**——开源工单（help desk）系统；
3. **WonderCMS**——扁平化文件型 CMS。

选型必须同时满足：可在隔离网络内本地 Docker 化部署、代码规模足以检验 LLM 审计能力、存在权威公开漏洞记录以支撑真值集（T1），且审计全程只针对本地副本，不触碰任何线上系统。

## 4. 各候选详细评估

### 4.1 phpMyFAQ（推荐）

- **运行环境**：4.1 线要求 PHP 8.3+，支持 MySQL/MariaDB、PostgreSQL、SQLite、SQL Server；官方提供 Docker 镜像与 docker-compose、Kubernetes 部署清单，容器化路径成熟。
- **代码规模（实测，非估算）**：核心命名空间 `phpMyFAQ/` 下有 **406 个 PHP 文件**；含第三方依赖后整个应用共 **8700 个 PHP 文件**；Composer 生产依赖经 `composer.lock` 锁定（含 Symfony 7.3、Twig、Monolog、Guzzle、phpseclib 等）。
- **攻击面**：具备多用户角色与后台权限、REST API、全文检索、附件/图片上传、LDAP、2FA 等，输入入口与污点路径丰富，可覆盖 SQL 注入、通配符注入、权限/上传等多类漏洞。
- **真值对齐**：锁定版本 **4.1.1（2026-03-31）** 早于 4.1.2，保留了修复前的已知漏洞，使 T1 真值集具备权威公开依据（详见 D-C02）。
- **部署验证**：已在 WSL 基于本地 `php:8.4-apache` + `mariadb:11.4` 缓存镜像离线自建成功，Web 服务在 `127.0.0.1:18090` 可访问，安装向导标题确认为 "phpMyFAQ 4.1.1 Setup"。

### 4.2 osTicket（落选）

- 最新 1.18.3 要求 PHP 8.2–8.4、MySQL 5.5+，功能成熟、权限体系完整。
- **无官方 Docker 镜像**，且官方不正式支持 Nginx；在隔离网络中需手工配置 Web 服务器与依赖，部署与复现成本明显高于 phpMyFAQ。
- 代码体量更大，离线环境下的构建与冻结步骤更繁琐，不利于在限定周期内完成可重复的环境交付。

### 4.3 WonderCMS（落选）

- 最新 3.6.0，要求 PHP 7.4+（cURL、mbstring、Zip、mod_rewrite），采用 JSON 扁平文件存储、**无数据库**，仅单一管理员。
- 规模极小（约 5 个核心文件、安装包约 0.17 MB），**攻击面与代码复杂度不足以充分检验 LLM 审计能力**。
- 无数据库意味着**无法覆盖 SQL 注入这一核心漏洞类型**；单管理员、无多用户体系，权限类漏洞也无法体现。
- 同样无官方 Docker 镜像。

## 5. 最终选定与版本锁定

### 选定结论

| 项目 | 锁定值 |
| --- | --- |
| 靶标应用 | **phpMyFAQ** |
| 锁定版本 | **4.1.1** |
| 上游发布日期 | **2026-03-31** |
| 运行环境 | PHP 8.4.27 + Apache 2.4.68 + MariaDB 11.4 |
| 本地访问地址 | `http://127.0.0.1:18090`（安装向导，未安装前 302 跳转 `./setup/`） |
| 审计用源码 | 剥离 `.git` 的冻结 ZIP（见 S-C07），含已预取并清理 `.git` 的依赖 |

### 选定理由

1. **任务清单既定优先项**：S-C04 明确标注 phpMyFAQ 优先，本评估结论与团队分工一致。
2. **容器化与离线可复现**：官方 Docker 生态成熟；本项目已验证可完全基于本地缓存镜像离线自建，无需访问 Docker Hub，构建确定性强。
3. **真值天然对齐**：4.1.1 早于 4.1.2，处于已知漏洞修复前，T1 可直接回溯权威 CVE/GHSA，避免人工构造真值的主观偏差。
4. **规模与攻击面适中**：406 个核心类、8700 个 PHP 文件、多用户权限与 REST API，复杂度足以检验 LLM 审计，又在可处理、可冻结范围内。
5. **技术栈完全匹配**：PHP 8.4 + MariaDB 与本地环境、tree-sitter PHP 解析器直接契合，可覆盖 SQL 注入等主要漏洞类型。

### 落选原因小结

- **osTicket**：无官方 Docker、不正式支持 Nginx，离线部署与复现成本高，体量更大。
- **WonderCMS**：规模过小、无数据库、单管理员，无法覆盖 SQL 注入与权限类漏洞，检验价值有限。
