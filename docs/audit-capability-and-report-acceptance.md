## 交付行为

- 新建审计冻结 `audit-capability-v1` 与原始目标来源。源码整包可读和风险关注范围分别表示。发现的目标关联由 Worker 提案、独立终审判读，宿主校验真实引用、归属与版本。显式分场景的其他类别不能自标为直接相关。附带发现保留台账；必要辅助链必须有输入到操作的证据与真实目标引用，不能独立达成目标。
- 完成性按 POC 模式分维度表达：off 和 auto 不设置动态通过数量门槛；required 保持至少一条目标相关兼容验证，现有同版本独立复核仍生效。执行、目标、源码/方向、风险义务、终审和交付材料分别记录。旧运行不回算完成性或清除有效验证。
- 可选 `bounded-v1` 深度风险义务，从真实 PHP 操作调用信号产生稳定、去重、最多 256 项的冻结集合。实际读取敏感操作行才能结算支持/无证据；宿主可按确切读取凭据关联任务，分派本身不算排查完成。只有目标相关必做项阻止完整收束。非相关/未知的可选导航信号保留待查，不进入强制终审批次；超限必做项保留明确缺口。
- `source_relations` 提供有界调用点、候选定义/调用者及 include 导航；同名歧义、动态关系缺口保留。结构化数据流节点继续经过实际源码读取区间校验，索引不是证据。
- 终审提交骨架提供精确批次、结论/验证版本、合法动作及目标引用区间，不预填接受、验证确认、完整读取或候选差异。目标关联错误按项一并反馈；格式错误后重给最小样板，有界纠正与原配额保持。窄条件同根因候选可更早进入整合，仍由模型裁定，不自动合并。
- 新 POC 结论增加实验合同：安全属性、攻击前身份、属主、状态、正常对照、攻击变量、预期/实际判别及两侧作业。写入需要实际读回，身份必须对应实际作业；仅 HTTP 成功或退出码不足以发布漏洞成立。已透传传统执行器、Claude 两阶段和持久队列的发布 schema，冻结结果保留合同。
- 新任务的知识路由采用通用取证方法加命中专题，记录理由、版本、字节量。共享源码缓存按快照/hash/文件状态验证，逐 Worker 的证据凭据独立。探索仅在实际新增源码窗口/依赖时有界追加，默认探索 6 请求，最多 10，仍预留发布与纠正、共享原单次及整次预算。

## 报告交付

报告抽屉增加执行报告、漏洞汇编和归档原件选择。运行发现可以解析其冻结规范结论；当前版本还需发现 ID、结论修订、评分修订全部一致，不以不同发现的相同修订号冒充当前版本。台账页只默认匹配结论修订、评分修订及事实内容完全一致的来源，否则要求明确选择历史版本。失败可读、重试保留原下载格式，切换会取消旧请求；未重新加入悬浮运行状态窗。

| 产物 | 内容 |
| --- | --- |
| 审计执行报告 | 原始目标、源码包、完成性、六列漏洞清单、文件/方向/风险缺口、材料待办、追溯 |
| 漏洞汇编 | 按终审接受、待审、存疑/排除分区，严重性稳定排序，共用单条模板和编号 |
| 单漏洞报告 | 源码证据、登录/状态前提、预期复现与实际观测、真实独立终审理由、完整 CVSS 3.1 向量、修复/复测、附件来源 |

原始段落、步骤与终审理由不静默截断；大段原始事实保留 JSON/附件。源码只取冻结片段，历史片段缺失或不全时说明。无实验不能写已复现；缺修复和复测列为交付待办，不删除已成立漏洞。

新布局校验与原 `quality_result` 分开：范围、计数、编号、证据/实验/复核归属、必需章节、锚点、围栏、窄表均检查。Markdown 对认证头、Cookie、令牌参数和 API 凭据脱敏；原 JSON/附件保持冻结事实，分别记录原始和呈现哈希。

## 接口与迁移

| 接口 | 合同 |
| --- | --- |
| `GET /api/runs/{id}/report?view=audit|vulnerabilities|archive&format=markdown|json|zip` | 省略 view 等于 archive，保留原响应字节与 ETag；阅读版使用独立哈希 |
| `GET /api/runs/{id}/canonical-findings/{canonical_id}/report?format=...` | 先校验父运行冻结规范列表归属；只导出该条引用闭包 |
| `GET /api/project-findings/{id}/reports` | 返回实际冻结来源、结论/评分修订与 `current` 标志，最新匹配优先 |
| `GET /api/runs/{id}/risk-obligations?offset=0&limit=20` | 有界义务及完整必做未决计数；同一能力供 Planner 只读工具使用 |

非法格式/视图返回 422；不存在或跨运行结论返回 404；运行未终结/新任务未冻结返回 `409 report_not_ready`；旧任务缺冻结事实/input 返回 `409 legacy_facts_unavailable`，归档仍可用。

加法迁移为 `findings.audit_metadata` 与 `derived_run_reports`。相关性、数据流、复测材料和新策略身份存于元数据，不回填旧结论。派生缓存键包含 frozen input、facts、原 output、renderer/template、视图、规范身份和格式；同输入固定 ZIP 顺序与时间。删除运行同事务清理缓存及冻结报告，迟到缓存写入不能复活已删除内容。不修改不可变触发器、历史状态、原始事件、原验证或 CVSS 口径。

新增阅读版、单漏洞导出与台账报告来源查询直接读取已保存的冻结行，不调用历史报告的惰性生成路径。缺少终审事实时返回明确 409，来源列表不列为可用报告；原归档和既有终审接口保留原兼容行为。

继续验收时对主库做只读备份，检查在私有临时副本上执行，不加载 Services/lifespan，不启动调度器；同时禁止外部 socket 连接和读取当前源码。主库共有 35 次运行、23 行冻结输入，其中 22 份已有终审事实。

## 实际边界

风险义务仅覆盖冻结的显式 PHP 操作信号，最多 256 项，不声称建立所有语言/动态框架/跨存储读回的完整风险图；非相关未知关系不会永远阻塞主任务。语义相关性与实验充分性仍需要模型独立判读，宿主只能确定性校验引用、版本、身份与已保存观测，不能自动证明所有语义。

本次没有进行全量 Lab30 真值评分、独立人员盲审或真实 POC 实验；实验合同通过假模型/假 runner 和持久队列回归。当前 runner 无崩溃后恰好执行一次协议，沿用未知提交不盲重投的边界。旧报告缺少脚本、修复或源码上下文时如实标为待补充，不通过新模型或当前台账补造。
