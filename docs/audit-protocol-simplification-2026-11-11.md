# 审计协议统一与运行简化

本轮基于 `61e30cd` 审视取证、POC、整合、终审和恢复链路。目标是减少重复表达、无关上下文和不必要的数据读取，使同一份事实按同一个合同进入裁决。源码真实性、利用链判断、反证、精确版本和真实实验要求继续由原有公共门禁校验。

## 简化清单

| 环节 | 当前重复或风险 | 本轮处理 |
| --- | --- | --- |
| 合法动作 | schema、提交绑定和数据库各自维护动作列表，容易出现提示允许、落库拒绝 | 共用 `review_policy.allowed_review_decisions`。阶段、对象类型、必做方向及 `can_resolve=false` 使用相同规则 |
| 对照判断 | 模型既填 `comparison_assessments`，又手抄 `distinct_from` | 模型提交一次显式关系与依据，宿主生成索引；JSON 发布和 Store 事务使用同一归一化函数 |
| 源码正文 | 关联结论重复携带完全相同的源码片段 | 同一请求内按完整对象的 SHA-256 保存单份正文，各项保留有序引用；内容有任何差异就不会共用 |
| 同伴正文 | 同一 peer 的完整描述在多个 item 内重复出现 | 完整对照对象按同样方式无损复用；合同仍列出每项实际 peer ID，不复用判决 |
| 终审提示 | 语义规则、合法动作、字段说明多处重复，静态规则位于动态数据之后 | 语义规则集中于稳定系统前缀；目标、事实、当前合同、schema 和结构示例由一个构造函数组装 |
| 引用字段 | schema 为每个对象重复展开全部源码路径和行号边界 | 优先使用已有的短 `evidence_refs`；旧坐标字段保留类型描述，精确区间仍由统一 `validate_focus` 校验 |
| 任务与方向读取 | 普通 finding 复核也加载整个任务／方向账本及尝试历史 | 只在实际存在相关调度动作或方向 resolve 时加载；纯 finding 和 risk 裁决不额外读取无关账本 |
| 判重写入 | 每次 duplicate 都重新加载所有 finding 及实验历史以定位同一台账组 | 用带 `run_id` 和组身份的 SQL 选出待更新记录，保持原事务内整组处置 |
| Worker 重报 | 完整报告重写会浪费生成和后续审查 | 沿用已有 finding 短索引、`finding_references` 与新旧坐标差异合同，不增加一套模型判重服务 |
| 实验与恢复 | 同一实验被重复执行、暂停后重新花费历史额度 | 沿用现有 job/verification 精确身份、持续 POC 队列、显式有界复测及同记录预算检查点 |
| 终审继承 | 无事实变化的已接受结论重复裁决 | 沿用已实现的 `incremental-v1`；本轮不重写历史签名或自动赋予新决定 |

前八项为本轮落地，后三项为已核对并继续使用的既有机制。统一的是引用、动作、归一化和数据交付，风险处置 `supported` 与目标关系 `supporting` 仍是不同概念，不合并成一个含糊状态。

## 对照判断只写一次

新的模型提交只需给真实的逐项判读：

```json
{
  "comparison_assessments": [
    {
      "item_id": "当前合同提供的规范同伴 ID",
      "relation": "distinct",
      "rationale": "指出实际输入、危险操作或必要利用前提的具体差异。"
    }
  ]
}
```

宿主从显式 `distinct` 判断生成 `distinct_from`，保存格式继续兼容已有报告。旧客户端提供一致索引时仍可提交；省略值或模型默认空数组可以补齐，非空错误引用或矛盾索引会拒绝。只给索引而没有判读，不会被补造为有效差异；`same_root`、`unresolved` 也不会被改成 distinct。去重目标、接受、确认、相关性仍由审查者判断。

模型侧 schema 不再要求填写派生索引；Store 的来源、阶段、版本、完整输入、反证及逐项判读校验继续执行。`review_example` 仍可直接解析为完整 `PlannerDecision`；短引用先经宿主绑定再解析。旧式显式源码坐标也仍可解析，越界、跨对象、跨未读空隙的引用由同一正式门禁拒绝。

## 请求内无损复用

`review_prompt.review_prompt_data` 只改变模型请求中的排列方式：

- `shared_source_excerpts` 保存原始源码对象，`source_excerpt_refs` 保留每项的原顺序。
- `shared_comparison_candidates` 保存完整 peer 对象，`payload.comparison_candidate_refs` 保留每项原有对照清单。
- 键根据完整 JSON 内容计算，不以相同文件名、坐标或近义文本猜测一致性。不同正文、版本、比较依据分别保留。
- 每份引用的完整正文都在同一请求中，不依赖模型记忆、旧会话、额外读取或外部缓存；判决仍使用合同的规范 ID。
- 若没有重复或引用包装反而增加字节，保持内联；可逐项还原为原始批次对象。

没有缓存相似问题的模型答案。原始租约、分页游标、来源证据、事实版本及冻结报告不使用这份展示投影作为替代，宿主仍先完整组装、校验实际事实，再进行请求容量检查。

## 验证与实际节省边界

在相同合成源码、任务与候选构造下，比较基线与本轮真实 Planner 驱动层发出的完整消息文本。结果来自受控模型，每种输入各一轮，都是 1 次请求、0 次工具；没有调用供应商或执行 POC。

| 场景 | 基线请求文本 | 本轮请求文本 | 减少 |
| --- | ---: | ---: | ---: |
| 单条静态审查 | 20,739 B | 16,447 B | 20.7% |
| 四条关联候选 | 90,280 B | 72,011 B | 20.2% |

公共系统前缀从 1,006 B 调整为 3,633 B，其余对象与当前引用放在用户数据中。数字为完整消息文本的 UTF-8 字节，不是实际供应商 token、缓存命中率或账单降幅，也不能用该受控输入推断真实模型的首轮正确率。现有 `run.usage.prompt_cache` 和逐角色输入／输出用量可用于后续实际运行核对；缓存命中仍消耗请求额度，减少拒收和重跑才会减少调用次数。

原记录 `3b50dbaf…` 的 **47 个历史租约**全部通过逐对象还原与字节非增加检查，冻结报告 input/output 哈希一致。这批租约的内联部分没有可去重收益，不能把上述合成样例的比例直接套到历史运行；分页恢复后的完整旧请求没有在此回放中重建。原始已完成记录未重跑。

新增回归覆盖单次判读及 Store 落库、旧索引冲突、非 distinct 不能冒充接受、动作合同一致、源码／peer 无损还原、内容变化不误复用、无重复不膨胀、纯 finding 不加载任务历史，以及真实模型驱动层的一次发布。复测、终审继承、方向结算、动态确认、分页、错误额度与冻结报告的现有回归一并验证。具体结果、源文件指纹、日志与范围见[验证记录](validation/audit-protocol-simplification-2026-11-11.json)。

最终后端全量 **2647 项通过**，其中新增 **22 项**；四个独立进程分别为 662／662／662／661 项，测试临时数据位于 `/dev/shm`。运行期间后端源文件和测试的合并哈希未变，保留已有重复 ZIP 文件名告警。较早的 171 项定向回归和最终兼容性回归 91 项有交集，不额外相加。归档 7 项哈希及原 22 TP／8 FN 评分重算一致；前端未变更。本轮没有额外模型请求或 runner 作业。

## 下一步简化优先级

1. **整合和终审按事实分工。** 整合只处理必要的去重、冲突与取证交接；终审只追加尚未判读的源码事实、动态结果和目标关系。不要把 `retain` 自动改成 `accept`，应先设计可复用的子判断及其依赖。
2. **进一步细分复审依赖。** 目前增量签名仍包含评分和完整验证记录。后续可分开源码成立性、实验观测和评级，评分或展示元数据变化只刷新相应部分；源码、权限、配置、攻击侧观测或反证变化必须重新判读。先明确迁移及反证失效测试，再调整旧签名。
3. **分开审查完成与目标达成。** 当前 `audit_complete` 仍要求至少一条目标相关的已接受漏洞。通用审计应能表达“已完成检查、未发现漏洞”；高召回与基准验收再要求覆盖、风险和指定动态目标。这个产品语义不在本轮悄悄改写。
4. **按真实失败类型优化纠正。** 将字段绑定、正文容量和语义缺证分别统计。优先处理同对象重复拒收、无新事实的复测和无关上下文，不以更高缓存率掩盖更多调用。继续保留每对象版本的持久化纠错上限。

本轮修改落在新审计、仅补终审、复测后终审及继续源码审计共用的请求与 Store 路径。未增加供应商专有参数；现有服务加载更新后即可使用，历史报告不回写。
