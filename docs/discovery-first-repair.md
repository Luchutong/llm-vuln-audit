## 冻结政策与阶段预算

`TaskSpec.workflow_policy` 可取 `legacy`、`discovery_first`，历史加载默认 `legacy`。
新建交互式全量覆盖复核默认 `discovery_first`；客户端明确提供 `legacy` 时保留原流程。
旧 Prompt 实验即使冻结清单没有这个字段，也显式按 `legacy` 创建试次，不继承新的交互默认。

POC 开启时，256 次总请求分配为源码规划与挖掘 180、POC 64、验证复核与收束 12。
POC 关闭时分配为 244/0/12。其它总额度按同一比例确定性取整，三者之和不超过总额，
至少保留一次源码请求。失败请求及历史摘要同样计费。
请求可用 `task.workflow_limits={discovery,poc,review}` 显式指定三阶段配额（创建面板的“阶段请求配额”），
校验规则见 [API 契约](api-contract.md)；创建时冻结，未用满的部分并入源码挖掘，`workflow.source`
记录为 `explicit`，未指定时为 `derived`。

配额和实际用量保存在执行状态中；新增的 `workflow` JSON 列默认为空对象，旧记录不会被升级为新政策。
暂停和恢复不清零，不同阶段来回切换也不清零。只有完整静态前沿与方向已结算时，未用静态额度才转入 POC；
最终复核额度不能挪用。最长预留 60 秒（短运行按总时长 5%），请求超时同时受当前阶段和全局剩余时间限制。
Planner 回合也从同一总上限内预留：默认 24 轮中的 6 轮留给复核，静态阶段最多使用 18 轮；
低回合配置至少留一个静态回合，不通过阶段切换扩张总回合数。

阶段停止使用 `stage_budget_exhausted`，保留成果并进入后续阶段；硬总预算、取消、执行代次和迟到写入门禁仍优先。
静态有界停止也可验证已有结论，但未决方向不能因此变成安全或已完成。
每批最多两条验证，再交给 Planner 读取证据和提交复核；verified、rejected 和 inconclusive 波次都得到检查机会。
未复核的 verified 结论不会促成收束，也不继续堆积后续验证。
验证开始前检查至少一次执行及三次结论发布的额度，不足时保留待验证状态。复核阶段直接进入结果读取，
不再侦察项目或启动新的源码任务；缺少实际两侧观测读取的复核仍会被拒绝。

## 未决方向与任务范围

宿主将 Worker 的 `remaining_work` 捕获为带稳定 ID 的方向记录，保存在既有任务 JSON 中。
Planner 使用 `direction_updates` 分派方向、引用已完成任务和有效发现结算，或记录具体跳过依据。
方向列表支持分页；关闭条件使用全量未结算集合，不能把未展示的方向当成完成。

Planner 工具 `list_directions(state="open", cursor=0, limit=20)` 返回
`items,total,unsettled_total,offset,limit,next_cursor`。`state` 支持
`open/all/pending/assigned/resolved/skipped`，页长为 1–40；按 `next_cursor` 继续读取。
决策中的 `direction_updates` 每轮最多 64 条，每项形如：

```json
{
  "direction_id": "dir_0123456789abcdef0123456789abcdef",
  "action": "assign",
  "task_key": "account-review",
  "finding_ids": [],
  "rationale_summary": "将账号权限边界的剩余取证交给该窄任务。"
}
```

ID 必须来自本轮宿主列表；`assign` 必须指定可派发的本轮任务；`resolve` 必须引用本轮当前有效发现，
或已有实际读账本的已完成任务。`skip` 需要具体理由，保留为范围限制，不能据此宣称安全。
同一方向每轮只能更新一次。任务定义也可用 `direction_ids` 显式选择待办，与分派更新必须一致。

窄任务重开只接收已分派方向；其它旧方向转为未分派待办。新线索不会反复扩大已经缩小的任务。
真正增加源码证据或新结论的成功小批不消耗失败重试计数，但每批仍计入共享总尝试、请求和时间。
无进展或失败仍受任务上限约束，重开不会扩大冻结的全局尝试上限。

初始上下文默认只补入显式选择和直接 include 依赖。共享 bootstrap 的反向入口作为导航线索，
不再自动预载全站。需要追踪调用者时可显式选择。日志区分选择、依赖补充和遗漏原因。
Worker 取得与当前任务相关的本轮累计结论摘要，保留 ID、类型、坐标、操作和前提，避免只记得上一批。
`fresh` 不接收其它运行的历史结论；重复处置与原有保守判重门槛不放宽。

## POC 证据与事实保存

HTTP、脚本及浏览器采用统一执行完成合同：上下文和身份前提匹配，没有超时或执行错误。
HTTP 的 3xx/4xx/5xx 是响应观测，不被等同于执行失败，也不被等同于漏洞成立。
证据引用新增 `body`、`headers`；响应头按宿主固定格式读取，原文引用仍须准确匹配实际作业。
旧 HTTP `body_text` 引用兼容。XSS 优先按规范类型识别，仍要求攻击侧有效浏览器执行证据。

账号前提字段先在宿主校验；角色通过配置身份核对。提供内存 URL 编码工具，宿主不开放网络导入。
额度耗尽或不可恢复前提错误后撤回工具，POC 最终结论采用 JSON，最多三次请求。
验证队列每个本轮台账只选择当前有效版本，历史版本和失效验证保留追溯。

作业返回即保存 ID 与已知执行事实；未有结论时 `verification_id` 为空，形成结论后关联同一事实记录。
终态事务将未完成认领标为中断，保留原作业 ID，不调用模型补结论，也不重放可能产生副作用的脚本。
未确认 runner 作业结束时仍保留上下文租约，不能把目标交给下一实验。
