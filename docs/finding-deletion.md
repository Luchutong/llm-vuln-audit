# 漏洞删除与重新开始全量测试

## 使用入口

源码包工作台的「漏洞发现」页可删除单条漏洞，或点击「清空本项目漏洞」。全局「漏洞发现」页在选择源码包后清空该项目，未选择源码包时提供「清空全部漏洞」。独立漏洞详情也提供「删除漏洞」。操作均需在弹窗中确认。

清空覆盖所选项目的所有结论，包括已撤回、重复、被取代的结论和未进入台账的历史发现、排查记录。搜索词、严重性、验证状态和分页不限制清空范围；需要保留其他源码包时使用项目清空。

开始一次不继承旧漏洞的全量测试：

1. 取消或完成该项目的排队、运行和暂停任务，等待执行停止。
2. 打开该源码包的「漏洞发现」，点击「清空本项目漏洞」并确认。
3. 使用已上传 ZIP 新建全量审计；新任务冻结的漏洞基线为空。

## HTTP 接口

| 方法与路径 | 范围 |
| --- | --- |
| `DELETE /api/project-findings/{ledger_id}` | 一条项目台账及其关联历史发现 |
| `DELETE /api/project-findings?project_id={project_id}` | 一个源码项目的全部漏洞及历史发现 |
| `DELETE /api/projects/{project_id}/findings` | 项目清空的等价入口 |
| `DELETE /api/project-findings` | 所有源码项目及旧版未归组运行的全部发现 |

`ledger_id` 为项目台账 ID，区别于单次运行的发现 ID。集合删除接口只接受 `project_id`，携带搜索筛选参数或空 `project_id` 返回 422，避免把列表筛选误当成删除范围。

成功返回 200，例如：

```json
{
  "project_id": "source-project-id",
  "affected_project_ids": ["source-project-id"],
  "deleted_project_findings": 2,
  "deleted_run_findings": 5,
  "deleted": {
    "project_findings": 2,
    "findings": 5,
    "verifications": 3,
    "project_baselines": 2
  }
}
```

`deleted` 包含实际涉及各表的计数；`project_baselines` 是移除已删除结论的历史运行基线数量。单条删除还返回 `project_finding_id`。不存在的台账或项目返回 404。清空空项目、重复执行集合清空仍成功并返回零计数。

所选范围内存在未终止任务，或终止任务仍有宿主执行占用时返回 409，整个事务不删除任何内容。项目清空不因其他项目的普通活动任务而失败；跨项目历史基线确实引用待删结论时，也必须先等待相关任务停止。

## 清理范围与一致性

删除会清理项目台账、关联的单次运行发现、验证及复核、CVSS 历史、POC 作业与尝试记录、跨任务关系和发现归因，并移除历史冻结基线中的对应引用。项目级清空同时处理没有台账关联的旧版发现。清理后列表及统计刷新，旧详情和对应 POC 下载返回 404。

源码 ZIP、项目、审计任务及已记录事件、计划和摘要保留；这些历史文本仍可能提及删除前的结论。独立 Prompt 实验的冻结数据、成绩和导出文件不变。本功能不删除独立归档文件，也不重置 Lab30 的账号、数据库或文件状态。

删除在一个 SQLite 写事务内完成，活动检查失败时回滚。服务重启的旧数据回填没有可恢复的来源发现，因此不会重新生成已删台账。新审计在创建事务内读取当前台账，避免并发清理后仍写入旧基线。

## 离线验收

- `backend/tests/test_finding_deletion.py`：级联清理、项目隔离、活动占用、空库、重启回填和基线并发保护。
- `backend/tests/test_finding_deletion_api.py`：接口范围、状态码、旧详情及 POC 失效、新任务空基线。
- `frontend/tests/records.test.mjs`：作用范围、活动任务保护和删除请求。
- `scripts/ui_finding_deletion_smoke.py`：模拟 API 下的真实浏览器操作，覆盖确认取消、重复提交、409/503 重试、清空后的空状态，以及深浅主题的 1440、1024、768、390px 布局。

所有验收使用临时数据库或内存模拟接口，不清空实际项目库，不调用模型或操作现有靶场。

本次验收结果：后端完整回归 1256 项通过，最终删除专项 23 项通过；前端 `npm test` 82 项通过，`npm run build` 通过；浏览器新增删除检查 14 项、源码包检查 76 项、原记录管理检查 25 项均通过。完整回归与删除专项有重叠，不相加计算用例总数。

使用 `scripts/start.sh` 启动的后端未开启热重载，更新后需重启本地服务以加载新增接口。
