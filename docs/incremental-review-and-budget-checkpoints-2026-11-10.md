# 增量终审与同记录补预算检查点

用户要求：关联任务只补未闭环方向；阶段额度不足时暂停，允许在原记录追加预算，不自动跳过 POC 后冻结为未决。

## 误重审的来源与修复

此前继续任务会主动排除所选复测项及关联候选的既有终审，并把 `worker_references` 纳入 finding 的版本签名。同一结论被另一个 worker 再读一次、或同伴被选择复测，就可能触发重复终审。历史 CVSS 来源及 runner 原始观测中的 ID 也不应被重映射：这些是原始来源，不是新任务的归属引用。

新任务及继续任务冻结 `review_reuse_policy=incremental-v1`：

- 按主张、版本、源码证据、评分、验证事实及冲突核对继承判决，保留来源运行。已接受且事实一致的结论不再调用模型。
- 新增读取／复用引用仍展示给 reviewer，但不单独使既有判决失效。新验证结果只使对应结论进入复核，不连带重审未变化的同伴。
- 关联候选、合法引用、已通过的同伴判决仍完整提供；待判读的关联候选保持共同判读。某候选被判重复后退出有效集合，不会使同批刚接受的主结论再次失效。
- 已结算方向保留宿主状态；引用在复制后重新绑定本地 ID 及内容指纹，不恢复成旧的 assigned 状态。
- `risk_fact_policy=operation-v2` 不因一般补读或相邻 finding 的非否定验证状态变化重审源码义务。动态反证、主张／证据变化、显式分派结果变化仍重开相关项。历史 `operation-v1` 签名保持兼容。

新验证的正常／攻击观测和实质变化仍须接受对应复核；不一致的内容不能继承父任务的“通过”。

## 阶段预算不足的行为

新宿主队列任务采用 `budget_exhaustion_policy=pause-v1`：源码、POC、终审的阶段请求／时间边界，以及整次请求／工具／时间上限，均形成 **paused 检查点**。保留原阶段、open 目标、待办、验证及逐项错误账本，不因预算不足生成终态冻结报告。阶段耗尽后，动态预留不能先调拨其他阶段额度绕过暂停。

POC 在认领下一项前发现配额不足，会在认领、复位和调用模型前暂停。在途实验沿用既有关闭及观测保留机制；已提交、未确认或已中断的作业不自动重放。增加预算不等于验证成立。

历史终态报告保持不可变；未升级的历史记录保持冻结策略。当前静止暂停记录可通过受约束的迁移接入新行为。

## 同记录追加预算

暂停后点击 **“追加预算并继续”**，选择一档预设：

| 预设 | 新增模型请求 | 新增工具调用 | 新增时间 |
| --- | ---: | ---: | ---: |
| 小幅补充 | 64 | 512 | 30 分钟 |
| 继续一轮（默认） | 128 | 1024 | 60 分钟 |
| 深入补查 | 256 | 2048 | 90 分钟 |

展开 **“微调额度”** 可分别修改三个值，时间以分钟填写，0 表示该项不增加。点击“追加并继续”后才提交。系统合并剩余额度，自动接续未完成工作，无需选择阶段或管理调拨。

`POST /api/runs/{run_id}/budget` 示例：

```json
{
  "request_id": "my-budget-grant-001",
  "responses": 32,
  "tools": 0,
  "seconds": 1800,
  "resume": true
}
```

`request_id` 幂等，网络重试不重复加额，改参数须使用新的 ID。接口默认 `stage=auto`，已有剩余额度与新增请求共享，宿主自动接续尚未完成的源码、验证或终审工作；累计阶段消耗、POC 原作业和纠错次数不重置。旧 API 的显式阶段参数保留兼容，但不再出现在默认界面。
