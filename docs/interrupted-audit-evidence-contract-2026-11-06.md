## 新合同 worker-evidence-v2

新建宿主队列审计默认冻结 `role_policy=worker-evidence-v2`。`worker-evidence-v1` 仍可显式指定，保留其原来的 sink 覆盖规则；缺失版本的历史运行继续沿用 legacy。没有数据库迁移、旧任务升级或历史报告回填。

界面的“基于原任务新建”不再将旧角色合同复制到新请求，由服务器冻结当前默认版本；被复制的原记录不变。需要固定旧合同的对照试验仍可通过 API 显式传入版本。直接续接旧冻结运行不会自动升级合同。

1. 每条 finding 仍必须提供实际读过的 input 与 sink，保留来源、传播与敏感操作。来源也可为真实持久化数据或配置，不要求编造请求输入。
2. 根因和 sink 同处时，sink 可以直接覆盖 primary_location。
3. 根因与 sink 分离时，提供唯一 `kind=root_cause` 节点，其 evidence 与主定位路径一致，且 `start_line <= primary_location.line <= end_line`。节点说明必须解释缺陷如何导向本条 sink。
4. 所有节点继续检查实际读取区间；不能移动主定位、把普通输入冒充根因、拉长 sink 范围或拼接未读行以通过格式。
5. 坐标校验不证明因果，独立审查仍需核对根因、输入与下游操作的联系，并拒绝误报、无关操作和重复主张。

例如，错误角色判断可作为 root_cause，后续查询或写入作为 sink；会话固定可在接受外部 SID 处定位根因，登录态写入仍作为下游操作。两处位置和类型保留各自实际语义。
