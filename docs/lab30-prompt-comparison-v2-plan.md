## 1. 目标与实验边界

课程要求是“多版本 Prompt 挖掘效果横向对比，量化说明优化提升”。
产品必须形成“选择真实策略版本 → 相同条件完整审计 → 独立评分 → 图表与逐项证据 → 可下载报告”的链路，
能回答各版本检出多少官方漏洞、增加或丢失哪些漏洞、是否稳定、消耗如何变化。

旧实验按答案预选文件、每文件选择一个单元，默认六个单元，绕过真实 Planner，提示词库与实验不相通，
也没有重复试验。按引用窗口贪心匹配会受到类别、宽引用和发现顺序影响。因此不能只加图表继续使用旧协议。

确定的边界：

- 使用原始 Lab30 ZIP、官方 30 项漏洞和 22 类，不增加安全负例，不修改原始答案。
- 实验只改变 Worker 审计策略；共享 Planner、工具、输出契约、证据门禁及 CVSS 3.1 计算。
- 默认三个版本、每版三次，共九个逻辑试次；主实验关闭自动 POC。
- 主成绩为官方清单匹配 Precision、Recall、F1，辅助展示 CVSS、资源及运行可靠性。
- 不把防御综合分、canary 或 POC 成功率混入挖掘排名；不自动更新普通审计的默认策略。
- 优化版本可以提升、持平或下降，结论由实际结果决定。

## 2. 策略版本与控制变量

### 2.1 W0/W1/W2 的递进设计

| 版本及固定 ID | 变化 | 需要实验检验的假设 |
| --- | --- | --- |
| W0 / `worker-w0-v1` | 基础风险识别、影响和源码主定位 | 建立基础能力 |
| W1 / `worker-w1-v1` | 增加输入、传播、危险操作及已有防护核对 | 是否减少依据不足的报告 |
| W2 / `worker-w2-v1` | 增加跨文件补读、身份、对象权限、配置及业务状态 | 是否改善跨文件与业务缺陷检出 |

策略必须放在真实 Worker 的独立槽位，不能通过 `instructions=` 替换整段宿主指令。
固定宿主契约、冻结策略、当前任务及上下文组合后执行；三个版本具有相同工具与安全边界。
策略中不得包含官方 ID、答案位置、攻击答案、预期命中数量或提示模型评分的文字。

提示词库增加 `kind=worker_strategy`、`contract_version=worker-strategy-v1`，保留父版本与优化原因。
用户可派生自定义策略参与实验。被审计或实验引用的策略只读，修改必须派生。
旧 P0/P1/P2 不是新策略协议，不得冒充 W 系列；旧实验读取冻结文本，缺失时明确“历史未保存”。

### 2.2 公平执行协议

每次使用生产 `AuditWorker`、真实 Planner、Worker、纠错、证据验证、发现落库与 CVSS 计算。
全部源码均是候选审计范围；不设置类别场景、不按答案选文件，也不设置找到第一条即停止。
实际读了多少源码、为何结束必须单独展示，不能把“全量候选范围”写成“每行均已检查”。

| 条件 | 默认 |
| --- | --- |
| 版本数量 | 3，允许选择 2–5 个兼容版本 |
| 重复次数 | 3，允许 1–5 次；不足三轮标为初步结果 |
| Worker 并发 | 每试次 1 |
| 试次执行 | 同一时间一个实验，试次串行 |
| POC | off |
| 每次调用预算 | 24 请求、96 工具、1800 秒 |
| 每次审计总预算 | 256 请求、2048 工具、1800 秒 |
| 全量目标 | `stop_on_achieved=false`，不设 `scenario` |

服务端校验预算并展示实际生效值。创建页显示完整九次预算上限，不能把单次预算误当成整个实验预算。
轮换顺序为第一轮 W0/W1/W2、第二轮 W1/W2/W0、第三轮 W2/W0/W1；其他版本数按循环移位。

### 2.3 冻结与隔离

实验创建时保存不可变 manifest，至少包含：

- 协议、源码 ZIP 摘要、真值文件及规范内容摘要、评分锚点摘要；
- 策略 ID、标签、父版本、原因、正文及正文摘要；
- 公共指令及实际模板摘要、执行策略、Git commit 与构建标识；
- 模型 ID、脱敏端点、thinking 和实际发送的采样参数；
- 全量目标、规划/尝试上限、并发、所有预算、排程与基线。

凭据不进入 manifest、浏览器、报告和日志；执行环境单独受控。运行中编辑提示词、切换当前模型档案，
不得改变已经冻结的实验。补跑也不能偷偷切换模型或端点。

每个“版本 × 轮次 × attempt”使用独立数据目录、数据库和会话，台账初始为空。
冻结的原始源码与真值资产分开；只有评分器读取答案。执行器不能实例化完整主站 `Services` 引发自动导入、
台账回填或实验 runner 初始化。历史读取必须使用只读模式，不得通过普通 Store 构造偷偷建表或迁移。

## 3. 评分、有效性与统计

### 3.1 新发现契约

所有新策略共用：

```json
{
  "vulnerability_type": "sqli",
  "primary_location": {"path": "真实快照完整相对路径", "line": 123}
}
```

主定位是根因或危险操作的实际一行，必须属于快照、已经读取且包含在本条已验证证据中。
行号是严格正整数，不接受布尔值、字符串、越界行。路径不接受绝对路径、遍历、basename 或任意后缀匹配。
类别按根因确定，反序列化导致的命令执行仍是 `insecure_deserialization`；不由另一个 LLM 判断类别。

固定类型为：

```text
auth_bypass, code_execution, command_injection, csrf, idor,
info_disclosure, insecure_deserialization, lfi, mass_assignment,
open_redirect, path_traversal, price_manipulation, race_condition,
rfi, session_fixation, sqli, ssrf, weak_crypto, weak_type_comparison,
xss_r, xss_s, xxe, other, unknown
```

未知和 other 发现保留，不能丢弃以美化分母。固定别名映射可归一化，无法唯一确定时不猜测。
新字段贯穿发现版本、事件、数据库、API和报告。已知且不同根因不得在精确指纹或模糊合并中合为一条；
缺少新字段的历史记录继续兼容，不能重写历史 ID。

### 3.2 锚点核验与最大匹配

`datasets/lab30-shop/scoring_anchors_v2.json` 独立保存全部 30 项关键坐标及逐行摘要，
`SCORING_V2.md` 记录核验表。已逐项读取原始 ZIP，明确区分跨文件入口和危险操作、
二次 SQL 的写入和执行、余额竞争与关闭会话锁。原始真值不修改。
实际共 43 个可接受关键坐标，重复坐标不表示额外真值。

`validate_assets(source_zip, truth, anchors)` 在任何付费执行前核对 ZIP SHA-256、真值摘要、ID/类型对应、
每个精确路径及每行 SHA-256。修改资产必须升级协议并重新核验，不能根据模型输出调整锚点。

`evaluate_v2(truth_payload, findings, anchors_payload)` 只读取本次当前仍主张且通过宿主验证的漏洞。
排查、撤回、标记重复和被替代的历史结论排除。按“根因兼容 + 精确主定位”建立二分图，
固定排序后取最大基数一对一匹配。发现顺序、CVSS 和置信度不能影响结果。

| 符号 | 定义 |
| --- | --- |
| TP | 匹配命中的真值数 |
| FN | 30−TP |
| D | 有匹配边但多余的当前报告 |
| U | 没有匹配边的当前报告 |
| 基准 FP | D+U |

```text
预测数 = TP + D + U
Precision = TP / (TP + D + U)
Recall = TP / 30
F1 = 2TP / (2TP + D + U + FN)
```

零报告：Precision=null，Recall/F1=0。U 并不等于已证伪漏洞，清单可能不完整；没有安全负例，
不提供 Accuracy、TN、真实误报率 FPR。宽证据范围不能替代精确主定位。
定位吻合但类别不符时保留诊断，主成绩不计 TP。每个数字必须能追溯到 trial、finding 和源码。

### 3.3 有效性、取消与补跑

运行终态与评分有效性分开保存，不能把框架 `failed` 直接等同于无效试验。

| 情况 | 处理 |
| --- | --- |
| 预算耗尽、格式错误、工具参数错、引用拒绝、上下文不足 | 有效，保留真实低产出 |
| 无法证明外部服务不可用的模糊超时 | 默认有效执行失败 |
| 明确的不可恢复连接故障、凭据失效、持续外部服务故障 | 基础设施无效 |
| 用户取消、进程崩溃、服务重启、产物损坏 | 无效，保留产物及已知消耗 |

无效试次不能静默删除、自动补跑或自动付费恢复。用户可对无效试次（含基础设施故障、取消及中断）显式补跑一次，
创建新 attempt，保留原 attempt；已经有效但成绩差的试次不能替换。再次无效则该轮不完整。
每完成一个 attempt 就持久化，不能等九次全结束。取消先阻止后续启动，等待当前子进程退出，
超时后强制结束；迟到结果不能覆盖 cancelled。重启将运行中状态标 interrupted，不自动重交。

### 3.4 重复统计与评级

`summarise_trials` 仅选取所有版本在同一轮都有效的共同轮集合。每版使用相同轮集合，
先独立评分再求均值和样本标准差，不取三轮并集、最好一轮或池化计数。
每项指标返回 `mean、sample_std、n、values`；n=1 时 SD=null，Precision 忽略 null 并显示自身有效 n。

相对基线先计算每轮差值再汇总，展示 ΔF1、ΔRecall 的百分点及每轮增检/丢失 ID。
`complete_rounds、complete_round_count、preliminary` 必须进入接口。不足三轮不能声称稳定提升，
三轮也不宣称统计显著或超出 Lab30 的普适效果。

CVSS 单独评价基础分 MAE、等级/分数一致及可评分覆盖率，不与 F1 加权。
既展示各版本自己的命中集合，也展示同轮全版本共同命中且均能评分的交集，注明分母。
CVSS 0.0 真值仍参与召回；缺失不计0；不能从重复报告另挑评分最准确的一条。

资源包含请求、工具、输入/输出/总 tokens、耗时、每 TP tokens、实际读取覆盖和终止原因。
无 TP 的单位成本缺失，未知 tokens 缺失，不能当零。实验实际总成本还包括失败、取消和补跑。
证据链字段完整率只表示字段非空，不能叫证据链正确率。canary、防御总分保留在旧协议或辅助位置。

## 4. 接口、页面与报告

### 4.1 接口与标识

沿用 `/api/prompt-experiments`，新创建请求声明 `protocol=lab30-full-v2`、实际 `prompt_ids`、
`baseline_prompt_id`、`repeats`、单次调用预算和整次总预算。基线必须在所选版本中，版本不重复，
均兼容 worker-strategy-v1；新协议拒绝 `units_limit` 或 `scenario`，防止只扫一部分却对全部真值排名。

查询返回 manifest、试次进度、每轮成绩、共同轮集合、汇总、差值及逐项矩阵。
试次详情、事件分页、证据源码、报告、补跑接口放在实验作用域：
`/api/prompt-experiments/{experiment_id}/trials/{trial_id}/...`。
保留取消，整组下载支持 Markdown、JSON、CSV。隔离 run 不能跳转主库 `#run/:id` 或普通 snapshot API。

明确区分 `experiment_id、trial_id、attempt_id、run_id、finding_id`。
主库保存索引和冻结信息，服务端确定隔离目录，客户端不能提供任意工作目录。
目录缺失显示明确状态/404，不创建空库、不回退其他 run。实验引用影响提示词只读与使用次数。

旧实验标为 `legacy_unit_v1`，不重算、不混排；普通审计不传新策略时保持生产默认。

### 4.2 前端交互

保留 `#experiments`，增加 `#experiments/:id`。基线在创建时冻结，临时查看其他对照不改写正式结果。
页面包括：

1. 配置：真实策略库、基线、重复次数、模型与总预算，明确 POC 关闭。
2. 进度：每个逻辑试次和 attempt、轮次、Planner/Worker 阶段、消耗和停止原因。
3. 总览：P/R/F1 分组柱状图与波动、ΔF1、逐轮表和资源表。
4. 明细：30 行真值命中矩阵、22 类图、D/U 和定位/类别不符诊断。
5. 版本：冻结正文、父版本、优化原因及相邻差异。
6. 追溯：所属隔离 trial 的发现、日志、证据源码和报告。

原生 SVG 配语义表格实现图表，沿用主题，不引入重图表依赖。不用雷达图或防御总分代替 P/R/F1。
矩阵显示命中次数/共同有效轮数，未完成轮明确说明；点击汇总格先选轮次再看具体 finding。
没有命中不等于已经证明源码安全。

页签、轮次、类别、对照版本和选中项写入 URL；刷新及前后退可恢复。
切换取消旧请求，轮询保留阅读和滚动位置。类别筛选只过滤显示，不改变正式成绩。
前端使用 Experiment/Trial/Attempt/TrialScore/AggregateMetric/TruthResult/FindingMatch 等具体类型，
不在结果通路使用 `unknown[]`。

### 4.3 导出和事实结论

所有展示与下载读取同一服务端评分对象，前端不另算一套成绩。
Markdown 保存条件、版本差异、逐轮成绩、波动、矩阵及事实结论；JSON 保存全量追溯；
CSV 提供 summary、trials、truth_matrix 三种表结构。下载完整实验，不随页面过滤器缩小范围。

自动结论使用确定性模板，不调用另一个 LLM。负差值写下降，F1 上升但 Recall 下降要同时说明，
各轮方向不一致必须显示不一致；数据不足不下优劣结论。不执行 POC 时不得写“已验证漏洞”或“利用成功率”。
报告保留清单不完整、无安全负例、小样本及资源缺失等实际解释边界。

## 5. 实施阶段与离线验收

| 阶段 | 交付与完成条件 |
| --- | --- |
| P0 | 30 项锚点、哈希、分类和新输出契约，固定匹配测试通过 |
| P1 | 策略槽贯通真实 Worker，新字段与跨类型去重保护，普通审计回归通过 |
| P2 | 独立试次、冻结、总预算、取消、补跑、只读历史和作用域追溯闭环 |
| P3 | 图表、矩阵、版本差异、事实结论及统一导出 |
| P4 | 后端、前端、Playwright离线回归及部署检查 |
| P5 | 操作人员显式启动真实九次实验，产出课程证据包 |

评分离线必测：

- 最大匹配例：A接受x:10或20，B接受x:10，f1在10、f2在20，必须TP=2。
- 增加同类f3在10及无匹配f4在30、另一个未命中真值：TP=2/D=1/U=1/FN=1，P=.5/R=2/3/F1=4/7。
- 同一行不同类型分别命中；同类重复不得代替另一类型；改变预测/真值顺序不改匹配。
- 同名不同目录、大小写、任意前缀、越界/布尔行号、宽证据不能误匹配；未知类型保留。
- 零报告、CVSS 0.0、缺失评分、共同CVSS交集、配对均值/样本SD、空Precision分母。
- 基础F1[.4,.5,.6]、优化[.5,.7,.6]：平均提升10百分点，差值样本SD=.1。
- 无效轮全版本共同排除，预算耗尽仍计，不能挑最好attempt；重复槽位拒绝。
- ZIP、truth、锚点行摘要改动在模型调用前拒绝。

执行回归必测：

- 九次无台账/会话继承，策略进入生产链，答案不入模型上下文。
- 运行中编辑提示词、切换档案、取消启动瞬间、退出和重启不产生额外模型执行。
- 失败、补跑、丢失隔离目录、旧记录缺字段和迟到结果有正确终态。
- 深浅主题及1440/1024/768/390px，页面无整体横向溢出，矩阵自身滚动。
- 图表、表格、CSV/JSON/Markdown数值及证据完全一致，直达/返回/刷新恢复。
