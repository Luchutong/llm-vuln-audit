# 审计输出精简与必要证据包

新版运行冻结 `output_policy=audit-evidence-v1`，用户交付物只有一份审计报告和配套证据 ZIP。宿主从冻结事实生成报告，不增加模型写报告的回合。原始证据、方向账本和恢复状态继续保留在内部。

## 输出逐项检查

| 输出 | 实际消费者 | 本轮处理 |
|---|---|---|
| Worker `summary` / `reasoning` | 任务结果、事件、Planner 的结果摘要 | 模型只写 `summary`；宿主将同一文本兼容写入旧 `reasoning`。显式提交的历史依据仍可解析，不重新推断结论 |
| Planner `basis_summary` / `next_action` / `report` | 决策落库；后两项主要用于展示 | 保留一段 `basis_summary`，新版 schema 移除后两项及不再被引用的定义；展示散文不能阻断结构化决策 |
| Worker `remediation` / `retest` | 报告、台账展示 | 新版不要求生成修复建议和修复后测试计划，不为缺填追加补证；已有内容仍可解析、保存和展示 |
| Worker `severity` | 兼容旧输入 | 不再要求模型重复给等级，宿主仍从 CVSS 指标计算 |
| Worker `poc` | 显式要求的脚本材料、验证线索 | `require_poc=false` 时从新版 worker schema 及脚本提示移除，由独立 POC Agent 在实际验证阶段生成实验；`true` 保留原要求 |
| `findings` / `finding_references` | 发现持久化、同根因补证、终审 | 保留，避免让已有结论变成新发现 |
| `observations` / `direction_results` / `candidate_updates` | 线索分流、反证、调查所有权和结算 | 保留，不把它们误当成用户报告散文而删除 |
| `remaining_work` / `next_focus` / `missing_context` | 有界调查、重试和未完成范围 | 保留，不为缩短输出丢掉真实方向和缺口 |
| `dataflow` / `primary_location` / 原始引用 / 利用前提 | 证据绑定、POC 范围、终审、复测 | 保留，继续区分输入、根因与实际 sink，继续要求真实读取 |
| 验证记录、正常/攻击观测、版本和正式复核 | 实际复测、增量继承、动态反证和终审 | 保留，不用一段摘要替代实验事实 |
| 独立报告视图、逐漏洞 Markdown、单独 JSON 下载 | 用户展示 | 正常界面收敛为两个下载按钮，漏洞详情不再逐项请求报告来源或生成下载变体 |
| 完整冻结输入、事实、事件、调试质量与评分 | 恢复、兼容、排错和实验分析 | 仍在内部保存；默认 ZIP 不再复制完整运行转储、质量诊断和评分报告 |

`retest` 是模型撰写的“修复后如何测试”文本，实际执行复测并不使用它。实际复测仍绑定 finding/revision、源码快照、实验、观测及审查版本。缺失会影响成立性的登录/权限/业务前提仍需明确报告。

## 唯一主报告与证据闭包

主报告同时列出目标、完成性、覆盖与未完成事项，以及接受、待审、存疑或排除的结论。每项包含主定位、因果链、利用前提、源码引用、CVSS 依据、独立处置和动态观测；继承实验明确标为继承验证。未审完和未运行不会被改写成完成或已复现。

ZIP 默认包含：

- `audit-report.md`：与单独下载相同的主报告。
- `evidence.json`：规范身份、当前结论及评分版本、冻结引用、去重的原文片段、相关实验和复核记录。保留完整证据，不再复制 peer 正文、整合建议和运行转储。
- `manifest.json`：文件哈希、源码片段定位与片段哈希、冻结来源和真实缺失项。
- `evidence/`：属于这些冻结记录的实际脚本、runner 清单与原始产物。

不再同时生成执行报告、漏洞汇编、逐漏洞报告和诊断附件。相同源码原文只在证据 JSON 中保存一份，各漏洞通过原始 evidence ID 关联；报告目录链接指向本文件内的结论。

附件继续执行所有权、路径和 SHA-256 校验，不按 ID 前缀捞取文件，也不重新访问 runner 或当前仓库补造历史证据。仅声明了适配脚本时才检查该脚本，仅 POC Agent 的执行记录要求 runner 清单；人工验证不会产生不存在的清单待办。真正声明但缺失的附件及校验失败仍列入 manifest。

## 冻结、兼容与生效范围

新建运行默认采用新版输出契约；旧记录缺少该字段时保持原解析语义，显式 `legacy` 继续保留。新建关联继续任务、仅补终审和 POC 复测，旧字段缺失时冻结新版，显式旧政策仍尊重父任务。原记录的冻结输入和报告字节不回写。

新版终态直接冻结精简 Markdown、证据 JSON 和 ZIP；正常下载读取已保存产物，不再重复渲染、全量计算事实哈希或另存相同的派生缓存。内部 JSON 是证据索引，并非新增的用户交付报告。

界面显式请求 `view=report`。后端默认 `view=archive` 和既有视图保留，供旧脚本与历史归档兼容；旧档案可以按冻结事实生成新版交付视图，缺少冻结事实时仍如实返回不可用。新 renderer 的模板版本参与派生缓存键，避免旧版附件检查结果残留。

当前源码与语义门禁没有降低：目标关联、同根因对照、动态反证、读取区间、根因/sink、方向反证和终审仍按原要求校验。内部日志未做破坏性清理。本轮没有改写“审计完成”和“发现目标达成”的现有产品语义。
