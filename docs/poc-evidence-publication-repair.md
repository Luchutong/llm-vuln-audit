## 定位到的三个问题

### 错误引用被直接降级，未进入纠错

5 条未决验证都包含不匹配作业原文的引用：

- 把 HTML、页面文本用 `...` 缩写后作为逐字引用；
- 删除中间行，再把不同位置的输出拼成单个 excerpt；
- 把 `state_changes` 中的状态变化写成脚本 `body_text` 原文。

这些涉及批量赋值、弱类型比较、反射 XSS、价格篡改和一条反序列化发现。
宿主拒绝伪造或改写的引用是正确行为，不能据此直接把这些验证改成 verified。

原 `host_check` 将错误候选原地降为 inconclusive 后正常返回；发布 gate 只在校验器抛出
`ValueError` 时触发 JSON 纠正。因此十条结论均只调用一次发布请求，五条引用错误没有获得纠正机会。
被降级的 summary 还可能保留“已确认”的原始措辞，与状态冲突。

### 结论上下文按整段 JSON 截断

旧结论提示把全部作业序列化后按 24KiB 直接截断。该轮 3 条验证触发了这一上限，
其中一条只展示 8 个作业中的 7 个 ID。截断可能破坏 JSON，并把最后的有效实验排除在模型视野之外。
HTTP 正文又在“其他观测”重复展示，额外占用上下文。

### 执行提示混淆证据不足与未触发

已有成功作业但引用不足时保留 `execution_status=not_triggered`，页面原文显示
“未观察到预期触发”。这一字段不能说明本次观测没有漏洞影响；本次未决的直接原因是证据引用未通过。

## 修复行为

1. 抽取纯 `evidence_errors`，保留所有上下文、身份前提、退出状态、超时和 XSS 浏览器门禁。
   结论发布的严格校验器对错误的 verified/rejected 引用拒绝发布，使用原有最多三次 JSON 请求纠正。
   不新增额度，不重新开放工具，不重新提交实验。
2. 提示要求复制短且连续的原文。不同位置分别引用，不能加省略号、改写 HTML 或把状态元数据冒充输出。
   原文自身包含省略号时仍按精确匹配处理，不使用关键字黑名单代替校验。
3. 纠正用尽仍以 inconclusive 保存诊断和原作业，清空不合格的适配脚本，summary 明确为无法确定。
   新增 `poc_evidence_rejected` 事件，记录作业及错误类型，不保存被拒绝的 excerpt 或模型长正文。
4. 作业上下文仍限 24KiB，改为结构化分配：保留全部宿主作业 ID、上下文、身份和执行事实，
   输出按通道给出连续原文片段、字符位置和省略数量。JSON 始终完整；省略标记位于元数据中，不能被当成证据。
   最紧情况下优先保留浏览器 dialogs/evaluated；无法展示的内容明确标记，不猜补或自动拼接。
5. 移除重复 HTTP 正文，发现提示包含规范 `vulnerability_type`，长元数据在序列化前裁剪。
   回放该轮已存的十份作业，新的作业区均低于 24KiB，全部作业 ID 和输出完整保留，无需裁剪。
6. 当前 POC 详情的执行文案改为“执行完成，尚无确定验证结论”。验证状态、诊断与作业历史仍分别展示，
   不修改历史枚举或数据库内容。
