# POC 持续会话队列与时间政策

实施日期：2026-10-30。适用于新建普通审计和显式创建的复测／继续任务；不改写历史运行、冻结报告或 Prompt 实验预算。

检查点、受控继续与断流只读回收见 [poc-checkpoint-recovery.md](poc-checkpoint-recovery.md)：新运行冻结 `poc_policy.progress_policy="bounded-evidence-v1"`，历史运行保持原政策。SDK 输出上限、thinking 策略与流进度元数据见 [poc-generation-policy.md](poc-generation-policy.md)。

## 行为变化

当服务端已经启用 `POC_RUNTIME=claude_sdk` 时，新建普通审计冻结 `poc_policy.session_policy=session-queue-v1`。宿主按当前规范实体及结论版本生成验证队列，顺序领取现有 `poc_attempts`；整个验证批次复用一个 `ClaudeSDKClient`，不再为每条漏洞启动执行、结论两个 CLI 进程。

SDK 会话保留对话上下文；宿主每次只授权一个 `finding_id + revision + context_id`。每项仍重新申请 runner 独占上下文、核对身份并隔离 Cookie，前一项结束后关闭上下文。数据库和文件仍然共享，状态污染及原有重置政策保持有效。不会自动重置当前 Lab30。

客户端可以浏览任务列表，但领取、版本选择、目标租约及阶段切换均由宿主负责。SDK Todo 不承担调度或持久化职责。暂停、取消、预算截止及进程重启不自动重放状态未知的作业；已发布结果复用，未决项通过原有复测入口另行领取新预算。

## 发布与证据

在既有 MCP 实验工具外增加：

| 工具 | 合同 |
| --- | --- |
| `get_verification_tasks(offset, limit)` | 分页查看本批任务，默认 25 条，返回总数和下一页偏移。 |
| `get_verification_evidence()` | 返回当前上下文的实际作业、前提、状态变化及宿主编号的原文引用。超过展示容量的引用不能使用。 |
| `publish_verification(...)` | 提交当前漏洞、版本、上下文及结构化结论；宿主校验后立即落库，不等待整队结束。 |

发布复用 `EvidenceRefTable`、`evidence_errors`、`host_check` 和 `record_automatic_verification_guarded`。正常／攻击引用必须来自本项成功完成、身份前提成立的作业。HTTP 状态不直接证明漏洞成立；XSS 继续要求攻击侧浏览器执行证据。未知、失败、超时、其他上下文和旧版本引用均被拒绝。

同一发布重复提交幂等，冲突重提被拒绝。发布成功立即收回实验工具；作业额度用完、前提不符或提交未确认时进入只读发布状态。有效响应遗漏发布时，允许同一会话中最多两次只读纠正，不重放实验。预算不足、SDK 出错或最终未能发布时，保留作业和未决事实，不补造 `verified` 或 `rejected`。

发布成功后若 SDK 继续叙述，宿主通过 `interrupt()` 结束本次响应，再向同一客户端发送下一项；同样用于停止已用尽发布纠正次数的响应。该操作不会依据耗时中断尚未判定的实验。控制通道失败时关闭会话，已经提交的结论仍保留。

发布事务仍使用现有验证、作业和尝试表，没有新增作业表或成本账本。由于发布发生在 SDK 最终响应之前，当时用量标记为 `awaiting_sdk_result`；收到 `ResultMessage` 后，仅补全同一条验证记录的用量元数据，不改业务结论。崩溃缺失的用量保持未知。

## 时间和成本

| 限制 | 持续队列政策 |
| --- | --- |
| 单项验证时长 | 仅提醒，不判失败，不强制切换下一项。新建审计来自冻结的 `POC_MAX_SECONDS`；复测页面可修改。 |
| 执行阶段 75% 时间切分 | 取消。 |
| 单项 SDK `max_turns`、实验／结论请求数 | 不用于截断新队列；旧字段仅供旧模式兼容。 |
| 整次运行与 POC 阶段请求、工具、时间 | 保持硬限制，逐次原子准入；不挪用统一终审预留。 |
| 单项 runner 作业数和作业超时 | 保留；执行失败／不确定提交仍占作业额。 |
| 模型请求总时长 | 新队列使用剩余整体／阶段窗口，不在持续收到数据时额外按旧 `POC_CLAUDE_REQUEST_SECONDS` 截断。 |
| 连接及响应流空闲超时 | 保留；空闲上限来自 `POC_CLAUDE_STREAM_IDLE_SECONDS`，默认 120 秒。断流保留未决，不作为反证。 |

运行总预算仍由创建页／复测页设置。排队、身份准备及 SDK 执行消耗同一个剩余窗口；不会为每项重新获得完整运行时长。实验准入临近最后请求／工具余额时停止新副作用，保护取证与发布空间。

真实 Messages 请求（包括 SDK 重试和压缩）仍由受控网关扣减 `run_execution_state`、workflow 和现有 `poc_request_quota`；新队列使用一个 run/epoch/queue scope，不再逐漏洞开立小额请求上限。模型输出不能指定成本归属、替换网关能力或切换 runner 上下文。

每个 SDK 最终响应产生一条 `poc_runtime_usage`。持续模式的 `usage` 是逐轮数据，`total_cost_usd` 是会话累计估算，记录中对费用取增量；出现未知或不连续时不伪造零消耗。费用只作 SDK 估算，真实请求硬计数仍来自宿主账本。此处理依据 [Anthropic 成本说明](https://code.claude.com/docs/en/agent-sdk/cost-tracking) 与 [Python SDK ResultMessage 合同](https://code.claude.com/docs/en/agent-sdk/python#resultmessage)。

## 前端反馈

- 执行页显示持久队列的已发布、执行中、待执行、延期／中断及复用数量，并可展开逐项状态。
- SDK 等待期间每 2 秒记录心跳；公开流只记录生成进度元数据，不保存思考文本或输出全文。
- 活动视图合并同项重复心跳，保留每次发布事件；原始日志仍可追溯全部心跳。
- 复测默认“持续会话队列 · 逐项发布”；单项时长明确显示为提醒，整次预算单独设置。
- 可显式选择“旧版逐项执行／结论”用于对照；其单项硬限额继续生效。

## 启用与兼容

1. 在当前任务结束后的正常维护窗口重启服务，加载新代码；不需要更换现有 SDK、DeepSeek 配置或网关凭据。
2. 新建普通审计自动采用队列政策；已结束任务从“复测与继续审计”创建关联任务，默认使用新队列。
3. 已在运行／暂停的旧任务不热切换；原始记录缺少该字段时继续使用原逐项政策。
4. Prompt 实验创建与补跑不经过普通审计的新默认注入，仍遵守冻结的 720／780／7200 秒和原评分口径。
5. 暂停／重启后以 SQLite 尝试状态为准，不恢复旧 CLI 的内存会话、不重交未知作业。继续处理尚未领取的任务会创建新的会话；需要重新实验的未决条目使用显式复测。

本次没有重启正在使用的服务、调用真实模型、启动新审计或重置靶场。
