## 4. P0：给 POC 真正可用的白盒上下文

### 4.1 初始源码上下文

当前 `_finding_block` 主要提供结论摘要、源码坐标和 POC，SDK 工具没有源码补读能力。为当前发现预载原始证据窗口，以及解释危险操作必需的直接依赖，不预载整个项目。

- 首批总量上限 24KiB UTF-8，最多 4 个文件。按证据重要性提供原始行号，额外窗口和省略数量明确展示。
- 源码必须来自证据实际对应的冻结快照；沿用发现通过宿主来源关系解析，不能改用项目最新 ZIP。无法解析时返回 `source_unavailable`，不猜路径。
- 同时提供源码归档版本和已知运行目标版本；不一致时标记适用性限制，不能用未核对的源码确认动态根因。
- 保留规范漏洞类型、输入、传播、前提和历史 POC；历史 POC 是待验证假设，不是成功事实。

新增 MCP 只读工具，供新政策使用：

```text
read_verification_source(path, start_line=1, end_line=120)
→ snapshot_id, path, sha256, start_line, end_line,
  lines:[{number,text}], truncated, next_start
```

单次最多 200 行、16KiB；路径/范围校验复用 `SourceRepository.read_source`，超出快照、布尔行号、反向范围等在读取前拒绝。宿主绑定 snapshot/context，模型不能指定别的快照。记录当前上下文的源码读取范围及调用预算；不提供宿主文件系统、Bash、Docker socket、审计数据库或答案目录入口。

### 4.2 先解释异常，再增加 payload

提示明确：出现空响应、相同截断位置或相同错误时，先检查调用关系及可用运行诊断，再决定下一次实验。禁止因为响应长度变化就宣布漏洞成立。

本次 LFI 的针对性离线用例必须包含：正常视图、缺失路径、目录外入口、该入口再次加载 bootstrap。Agent 应识别“可能重复加载并报错”的证据缺口，不能连续请求多个相同结构的入口，把每次相同截断都当成新进展。

## 5. P0：补充能支撑判断的受控运行诊断

Lab30 目前 `display_errors=Off`、`log_errors=On`，Apache 错误输出至容器 stderr。不得为了方便验证直接打开页面错误回显，也不得把全量 `docker logs`、数据库或主机权限交给模型。

### 5.1 采集与关联

- 为验证配置独立、可关闭的诊断采集。可采用挂载到 Web 根目录外的 PHP prepend/shutdown 观察器和内部诊断收集器；不改应用业务 PHP、不添加验证专用漏洞或可利用文件。
- 观察器只采集既有运行结果，不吞异常、不把 warning 转成 exception、不改变响应体、状态码、会话或权限。
- 每条受控 HTTP 请求由 runner/relay 注入宿主生成的请求关联 ID。外部同名 header 被覆盖，不能信任脚本自报的 ID。
- 诊断绑定 `target + context_id + job_id + request_id + target_version`。仅返回本次请求窗口的 PHP 错误及受控执行状态，脱敏 Cookie、凭据、请求正文和宿主路径。
- 采集器不得暴露在商城公开路由；使用现有控制网络/认证方式，runner 无权借此任意读文件或执行命令。
- 首批必须完成 HTTP 观测的诊断关联。浏览器子请求和 runner 脚本若尚不能可信关联，分别声明不支持；不能把时间相近的日志冒充其证据。脚本 stderr 仍只是脚本侧输出，不是商城 PHP 日志。

### 5.2 接口与证据合同

```text
runner GET /v1/jobs/{job_id}/diagnostics?cursor=...
MCP read_verification_diagnostics(job_id, cursor="")
→ available, reason, context_id, job_id, target_version,
  items:[{diagnostic_id,request_id,kind,message,source_path,line}],
  next_cursor, truncated
```

默认每页最多 20 条、8KiB；检查当前租约、作业归属及版本。没有能力、日志尚未到达、窗口已过期和确实没有错误须分别表示，不能把 `available=false` 解释为“没有错误”。健康接口声明按作业类型细分的诊断能力。

可信诊断可经宿主固定序列化加入证据表，新增 `server_diagnostics` 通道及 evidence_ref_id；原文只从已存诊断还原。不得将源代码推断、模型摘要或用户上传的“日志”放进该通道。

HTTP 完成与服务端错误分别记录。PHP fatal 本身不证明漏洞成立；只有正常/攻击对照、实际根因和引用一致时才能发布。诊断不可用仍允许诚实的 inconclusive。

## 6. P0：从等待模型结束改为证据检查点

### 6.1 状态与触发

新政策由宿主管理以下单项状态，保存在现有 attempt/agent JSON：

```text
experiment → checkpoint → experiment（有依据的新实验）
                        → publish → published
异常/阶段截止 → recover_readonly → inconclusive 或有依据的已发布结论
```

检查点在已确认完成的作业边界产生，以下任一条件触发：

1. 自上个检查点累计完成 2 个实验作业；resolve/status/源码导航不计实验。
2. 出现精确重复请求、重复脚本或已经观察过的结果，且没有声明新的判别目的。
3. 当前项超过 600 秒提醒，且近期没有新作业、补读证据或有效发布；单纯 SSE 字节和心跳不算业务进展。
4. 作业额临近上限，或 POC 阶段即将进入预留发布窗口。

HTTP 请求相同的判定必须包含身份、上下文和相关状态；不能把不同身份、CSRF、状态变化或必要复现合并。脚本只做精确 hash 比对，不用模糊文本相似度裁掉不同实验。必要重试须有理由，未知提交只能查询原作业。

### 6.2 检查点操作

- 原始作业仍立即落库。检查点记录执行了什么、已有观测、当前证据引用及缺口；已有事实可在前端显示，不必等正式发布。
- 在该次工具返回中附有界的检查点和宿主证据 ID，不额外调用模型生成进度，不重复回放完整 HTML。
- 将当前项切为只读检查点，保留源码、诊断、证据查询和发布；新副作用暂不准入。
- 增加 `continue_verification` 工具，参数包含检查点 ID、未解决的具体假设、已读依据、下一次实验以及预期能区分的结果。只有当前版本/上下文、新实验参数和剩余额度都合格才恢复实验。
- 工具参数在既有工具预算中计费；检查点不赠送请求、作业或时间。继续只是允许做一个明确的补证小批，完成两项后再次检查，不允许一个“继续全面排查”反复解锁。
- 无新判别方向时发布当前结论或带具体限制的 inconclusive，继续队列下一项。不得为了提高发布率把截断、200 或 exit 0 自动变成 verified/rejected。
- 不能在 runner 作业尚未确认完成时切换目标。SDK 中断和 AnyIO 取消域继续由原 actor 所在任务关闭，不能跨任务破坏会话。

### 6.3 缩小输出与保留事实

脚本输出正常/攻击侧的关键字段和唯一标记，避免反复打印完整导航 HTML。宿主仍保存有界原始输出及准确引用，不能在正文中添加省略号后充当原文。

检查点至少包含：`finding_id,revision,context_id,job_ids,new_observations,evidence_ref_ids,missing_evidence,next_action`。`new_observations` 中宿主事实与模型解释分开；未提交正常/攻击角色的作业只能叫“观测”，不能自动标为完整对照。

## 7. P0：断流后保留成果，并给发布留出真实窗口

### 7.1 时间与请求预留

- 修复 `workflow_view` 与准入检查对 `host-queue-v1` 跳过 `review_reserved_seconds` 的不一致。新政策下，POC 阶段截止必须早于整体截止，真正保护冻结/动态计算出的终审窗口。
- 当前项还应在 POC 窗口内保留最多 3 次发布/恢复请求和最多 60 秒恢复时间，清理最多 10 秒。预留均来自原额度，不按项累加扣费；上一项完成后未用额度可释放给下一项。
- 时间不足以支持执行、发布和清理时，不启动新副作用。动态预留提高时收紧当前截止；不得在切项、重连、暂停继续或重启时重置时钟或累计用量。
- 生成请求、runner 作业、SDK 等待和清理全部受阶段与全局截止限制。600 秒提醒不会直接产生失败结论，但也不能越过上述硬截止。

### 7.2 流异常与只读恢复

- 发生 `sdk_api_error`、断流或模型终局缺失时，先保存最新检查点、全部已知作业和公开诊断，不将观测字段清空。
- 原 SDK 确认关闭、没有未知 runner 作业且仍有预留时，可进入一次有界的只读恢复。优先复用现有结论运行器；新会话只获得宿主事实、证据表及结论 Schema，不开放实验工具。
- 最多 3 次请求，共享前述 60 秒窗口；只能修正 JSON、读取已有事实或发布，不自动重放任何脚本/HTTP。原会话没有确认退出时停止恢复，保留未决，不能绕过目标租约。
- 错误连接的实验不得自动作为 rejected。恢复成功必须通过原证据、身份、上下文和版本门禁；恢复失败由宿主保存事实摘要与缺口，不能补造模型的确定性结论。
- 原错误及恢复消耗单独可见；恢复不清除 `stream_connection_error` 记录，也不把最终状态伪装成全流程无异常。

### 8.2 反馈与指标

分别记录并展示，不能互相覆盖：

| 类别 | 内容 |
| --- | --- |
| 宿主存活 | 最近心跳、当前项耗时，不声称模型有新进展 |
| 模型请求 | 请求开始、首事件时间、最近流事件、事件类型计数、结束/断流及累计等待 |

网关增加限频的流进度/结束事件，只记录字节、类型、时间和使用量元数据。HTTP 200 不代表生成完整；keepalive/ping 不算业务进展。

前端分别合并心跳和模型进度，不再用最新心跳替换 `poc_queue_progress`。至少显示“等待本次模型响应多久”“距上次实验多久”“已有 N 个观测，尚未发布及原因”。失败后仍可直接查看已有作业和检查点。

按服务端同一统计对象输出 JSON、Markdown 和页面：实验耗时、模型等待、已执行/已发布数、重复/补证次数、恢复消耗及未完成原因。沿用结果与本轮新增结果分开，避免把继承的 verified 当成本轮成果。

## 10. 必须通过的验收

### 离线功能与边界

- **本次 LFI 回放**：重放已观察到的 1381/1242/1052 差异。没有服务端证据时只能保存差异及缺口；具备可信关联错误时可解释中断，仍须按实际证据范围判定影响，不直接升级任意文件读取/RCE。
- **源码**：原始行号、依赖、超长窗口、缺失来源、同项目不同 ZIP、错误路径、布尔行号、宿主文件和答案访问拒绝。
- **诊断**：已知/未知作业、外部伪造关联 ID、其它上下文/身份/版本、过期日志、日志缺失与无错误的区别；原响应内容及状态保持一致；脚本与浏览器未覆盖的能力不得误报已支持。
- **收束**：两次已完成实验进入检查点；重复试探不能无限解锁；不同身份、真正不同根因/前提和必要重试不被误合并；有明确新方向可有界继续；未知作业始终阻止切换目标。
- **断流**：模拟 2109 个持续事件后连接中断，作业与观测完整保留；只读恢复不调用实验；失败保留未决；发布成功后断流不覆盖已提交结论；迟到调用和旧版本均被拒绝。
- **预算**：可控时钟覆盖 POC/终审/恢复/清理的截止，预留不足不启动，切项及暂停恢复不重置；Mock 上游统计与 SQLite 真实请求账本一致，恢复最多三次且不借用终审额度。
- **反馈**：仅心跳时不显示模型进展；只有 thinking/工具参数时仍有元数据反馈；流持续但无业务进展可见；旧记录无需新增字段仍可阅读；新旧结果及费用口径明确。
