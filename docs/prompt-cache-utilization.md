# API 提示缓存利用率

日期：2026-11-10。请求布局 `stable-prefix-v1`，统计口径 `prompt-cache-v1`，新生成的终审报告渲染器为 `final-report/v3`。

## 改进依据

缓存收益取决于供应商实际复用的**相同输入前缀**。原实现存在三处可改进点：

- CodeAgent 的系统提示在工具与角色合同之前就插入随机 `audit_action_*` 边界，每次新建 worker 会较早出现前缀差异。
- Worker 把候选检查点、动态根因索引、已知结论、风险义务等放在系统指令中，而共享的完整 JSON schema 放在源码与任务之后。不同任务很早就打断前缀，后面的相同 schema 难以复用。Planner 又在项目结构概览之前输出当前回合号。
- 主模型只保存输入／输出 token 总数，丢失响应原文中的缓存计数；历史摘要没有独立的响应事件。SDK 已保存部分缓存数据，但零值用了 `or` 回退，可能被误判成未报告。

## 请求与校验

1. **稳定公共前缀。** CodeAgent 对外固定使用已支持的 `<code>…</code>`。解释器仍保留每实例随机内部边界，由 `PhaseGate` 提取后转换，代码语法、规模及工具检查继续生效。
2. **规则和任务数据分开。** Worker 的角色合同、CVSS 规则及按策略收窄的完整 schema 放在系统前缀；候选、知识参考、目标数据、既有结论及根因索引移入用户上下文。初始及发布前的最新根因索引都保留，版本竞争仍由宿主验证，不缓存旧的查询结果。
3. **冻结资料先于回合变量。** Planner 的项目概览先于当前回合号，回合间尽量复用相同项目资料。阶段、策略、工具变化仍按真实合同构造，不能为了命中率混用不适用的 schema 或隐藏 ID。
4. **命中不等于成功。** 被宿主拒绝的响应仍计入消耗与缓存统计；结果不直接复用，终审、复测及 SDK 验证的证据检查继续执行。

没有用无关文本填充输入来达到供应商缓存门槛；没有自动保活、预热、额外去重模型或降低证据要求。

## 查看与统计

运行主页面的执行摘要下方新增 **API 输入缓存**，运行中和结束后都可查看。展开可见命中 token、已报告缓存的输入 token、缓存写入、数据覆盖，以及 Worker、Planner、独立审查、侦察、历史摘要和 SDK 验证的分项数据。

API 为 `GET /api/runs/{id}` 返回的 `run.usage.prompt_cache`；实验用量也包含 `prompt_cache`。新生成的终审事实包在 `appendix.usage.prompt_cache` 冻结相同数据，并在 Markdown 附录展示；JSON 和证据包沿用同一事实包。历史冻结报告保持原样。

核心口径：

```text
输入 token 命中率 = sum(有效缓存读取 tokens) / sum(这些记录的完整输入 tokens)
数据覆盖率 = 同时报告有效缓存读取及完整输入总量的记录数 / 全部用量记录数
```

- 直接按 token 总量加权，不平均各请求的百分比。
- 普通模型响应、历史摘要每次记一条；SDK 的 `ResultMessage` 每阶段汇总记一条，**记录数不等于 SDK 的底层请求数**。不与 gateway 流事件重复相加。
- 未报告、负数、布尔值、明显矛盾的计数不解释为零命中。合法 `0` 显示 `0.0%`；零输入分母不计算百分比；部分数据明确标注覆盖范围。
- 缓存写入只累计已报告的数值；`write_reported_records` 单独记录写入字段覆盖，读取计数齐全不代表写入字段也齐全。
- 响应事件保存小型 usage 投影，不保存模型散文、密钥或隐藏推理。无响应或没有 usage 的失败不能补造 token 数。
- `run_prompt_cache` 保存事件游标和累计值，刷新／暂停／继续／重启不会清零或重复相加。只读实验归档使用内存增量投影，即使没有新表也能读取，不能为了统计改写归档。
- 旧主模型事件已经丢失原始缓存字段，无法准确补回。历史 SDK 事件若有真实计数可纳入，其余标为未报告。工具结果缓存和历史摘要的本地复用不冒充供应商缓存命中。

提示缓存通常减少**未复用输入的计费**，并不减少模型请求次数、输出 token 或本框架的请求硬预算。供应商若按请求次数／完整逻辑 token 扣套餐额度，实际抵扣规则应以其账单为准；本次不写死模型价格，也不把命中率称作账单降幅。

## 验证结果

[离线前缀对照](validation/prompt-cache-prefix-2026-11-10.json)使用相同合成源码及两组不同 finding ID，对照基线提交 `d639143` 与本次实现，并测量 smolagents 清理后实际 SDK 消息 JSON 的 UTF-8 字节：

| 场景 | 修改前公共前缀 | 修改后公共前缀 | 请求长度 |
| --- | ---: | ---: | --- |
| Worker 直接发布 | 14,306 B | 35,926 B | 39,154 → 39,167 B，基本相同 |
| 相同工具／角色的代码探索 | 1,756 B | 6,659 B | 6,823 → 6,659 B |

这是可复用前缀测量，**字节不等于 token，也不能当作实际缓存命中**。

[三次真实 Worker 小请求](validation/prompt-cache-live-2026-11-10.json)使用当前选中连接 `deepseek-flash`，仅使用测试合成源码，每次最多一次响应、零工具、最多 1024 输出 token，没有修改或恢复生产审计，也没有执行 POC：

| 本轮请求 | 输入 token | 缓存读取 token | 命中率 | 宿主输出校验 |
| --- | ---: | ---: | ---: | --- |
| 1 | 8,634 | 1,152 | 13.34% | 拒绝，没有新增纠正请求 |
| 2 | 8,629 | 7,680 | 89.00% | 拒绝，没有新增纠正请求 |
| 3 | 8,635 | 7,680 | 88.94% | 通过，1 条既有 finding 引用、0 条新 finding |

三次共 **25,898 输入 token，16,512 缓存读取 token，命中率 63.76%，数据覆盖 3/3**，约 13.5 秒、979 输出 token。首个请求已经存在少量缓存，不能把它当作严格冷启动基线。前两次输出被已有校验拒绝，探测未保存模型正文，也没有定位这两次各自的拒绝原因；不能据此宣称审计成功率提升。结果证明当前请求链路可获得真实前缀复用和可核实用量，尚未进行完整生产审计的成对费用比较。

新增 `backend/tests/test_prompt_cache.py` 的 22 项回归覆盖字段归一化、零值／未知、SDK 分母、加权比例、游标重启、运行中查询、删除清理、只读历史归档、历史摘要、随机内部边界、不同 Worker 的共享 schema、Planner 项目图顺序和报告冻结。后端全量 2454 项通过（613／530／617／694），前端 129 项通过，构建通过；既有 ZIP 重名及 Vite 大 chunk 提示保留。前端覆盖完整、部分、零命中、未知和无记录的文案。

## 生效

加载更新后的后端和前端即可，默认无需增加环境变量或供应商专有参数。已有依赖可通过 `./scripts/start.sh --skip-install` 启动；原先启用 POC 时保留 `--poc`。本次修改没有重启现有服务，也没有恢复暂停运行。服务重启后，新建任务和继续／复测链路会使用新的请求构造及用量记录；已经发出的请求不能追溯提高缓存命中。
