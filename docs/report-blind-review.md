# 终审报告盲审表

用于计划 §11.2 的语义质量评价。盲审只看**冻结事实包渲染出的报告与证据条目**，不看 run 的日志、模型提示词或原始对话；审阅者不知道结论来自哪个 runtime。

盲审不能替代自动验收：它不重跑审计、不修改历史运行、不重算评分，也不把「未匹配官方真值」直接判成误报。

## 1. 抽样

- 至少 20 条主结论（`canonical`），按台账分层抽取；每层至少 1 条。
- 同时覆盖：`accepted` / `contested` / `pending`、有/无正式复核、有/无 POC 验证、至少 2 条未完成运行。
- 每条只附：最终正文、证据条目（含来源类型与快照范围）、验证状态、未决项与冲突说明。
- 抽取与判读分开：抽取人记录抽样依据与哈希，审阅人只拿到条目。

## 2. 每条的六项判读

| 项 | 通过标准 |
|---|---|
| 根因与主定位 | 根因描述对应真实缺陷；`primary_location` 指向危险操作/sink，不是入口或赋值行 |
| 权限与利用前提 | 身份、角色、前置状态与源码要求一致；未把特权成功写成普通会员越权 |
| 观测充分性 | 已有作业/浏览器证据足以支撑结论；inconclusive 没有被写成 confirmed |
| CVSS 一致性 | 指标依据可追溯到附带的攻击场景；影响与评分方向一致 |
| 修复建议 | 针对根因，而不是只加输入过滤或只改提示词 |
| 未决与冲突披露 | 未决方向、版本冲突、失败验证、覆盖缺口都出现在正文，不与主结论混写 |

评分：`pass` / `partial` / `fail`，另记一句理由。六项任一 `fail` 即该条不通过；`partial` 计入待修正。

## 3. 硬性一致性错误（出现即整批不通过）

- 字典 `repr`、`None`/对象文本进入正文。
- 预期响应或示例被当作实际观测。
- 模型生成的代码片段被当作快照原文引用。
- 环境/工具失败被写成「漏洞不存在」的反证。
- 同一主结论出现两个并列版本且无冲突说明。
- 正文、页面、Markdown、JSON、ZIP 的计数或引用不一致。
- 证据条目引用的 job/片段不在该 run 的快照范围内。
