# PHP 源码目标审计报告目录

默认导出面向任意上传 PHP 源码的目标审计，不把项目假定为 Lab30，也不把所有结论强行归入 SQL 注入、XSS 或命令注入。固定漏洞实验的旧报告仍可按其历史格式复现；新目标任务按下面目录输出。

## 1. 任务概述与边界

记录源码快照名称与哈希、冻结范围、任务目标、验收条件、模型、预算、每个动态任务的最大尝试、任务总尝试上限、Planner 回合上限、worker 上限、POC 策略和最终状态。说明“不可达”只针对已冻结范围和已经由 Planner 穷尽的证据方向，不是对整个系统的绝对安全声明。

## 2. 执行方法与可追溯性

说明 ZIP 不可变快照、PHP 语法索引、冻结项目图（文件、符号、静态 include、调用点、模块聚合、高置信入口候选与未解析静态根）、worker 的只读工具与 Planner 的全量只读工具面（读源码、检索文本、目录树/符号大纲、覆盖统计、固定调查全文、内置侦察子 agent）、范围访问策略、预算和证据引用校验。解释 `top_level` 只是语法分片而非入口事实，高置信入口与未解析根都只用于 Planner 导航。项目图与 Planner 的读记录只用于规划，不能作为发现证据。说明事件先写 SQLite 再通过 SSE 推送；工具调用和结果通过 `call_id` 配对；说明 `pause` / `resume` 是回合边界的协作式停止，与 `cancel` 的差别。

模型提供的内容称为“审计依据摘要”或“决策依据”：它应陈述当前结论、已经读取的源码事实、引用和不确定项。不要记录或展示模型隐藏思维链、供应商 thinking delta、完整提示词或密钥。

## 3. Planner 任务图与多 worker 执行

展示主 Planner、项目图、持久化任务图和 worker 的关系。记录每个 Planner 回合的项目图/worker 依据摘要、**本轮态势**（前沿与已结算方向、已有结论、已固定调查）、任务创建与更新、更正（`reopen` 产生新尝试并保留旧尝试行）、依赖关系和下一步；记录每个动态任务的状态、认领 worker、尝试、初始多文件上下文、依赖摘要交接、可检索的受限同行工具轨迹、用量、错误和终止原因。同行轨迹只能作为线索，不能替代当前 worker 的源码证据。解释 `achieved`、`continue`、`no_evidence`、`blocked` 的差异，以及 `completed`、`unreachable`、`inconclusive`、`cancelled`、`interrupted` 的收束条件。被更正的结论以新版本写入同一槽位，旧文本存进存档版本，不物理删除。

## 4. 审计结果与源码证据

每条结果至少包含标题、类型、摘要和通过校验的原始行号。可选地记录风险等级、相关输入、数据/控制流、敏感操作、边界/防护、前置条件、POC 和修复建议。源码事实、路由清单、认证边界、配置来源、数据流和漏洞都使用同一通用结果模型；缺失字段不应以模板占位文本伪造。结论分三区呈现：证据校验通过、校验未通过、以及**已被 Planner 撤回 / 判为重复**（后者保留记录、单列，不计入本次运行的结论）；每条再给出它的版本号、存档的历史版本与派生来源。

每条漏洞结论附**自动验证块**：状态（已验证 / 未通过 / 未决 / 不适用 / 环境不可用 / 未验证 / 源码已变更）、验证结论、目标与安全级别、runner job id、命令、正常与攻击观测、适配脚本和产物。未验证、不适用与环境不可用单独成节，并明确写出「未验证不是排除」。判为 `rejected` 的结论保留源码证据，但不再支撑“目标已达成”；若 Planner 没有撤回，报告将其列入「自动验证未通过」。历史人工记录只读保留，标注为旧版本遗留，不参与当前判定。

## 5. 结论限制与后续动作

记录动态 include、运行时配置、跨服务调用、项目图的静态边界、模型/网络失败、共享尝试或 Planner 回合耗尽，以及自动验证的状态分布、失败原因（脚本无决定性结果、浏览器不可用、runner 不可用）。Planner 在收束复核回合提交的限制说明（`limitations`）写在这里；没有叙述时退回宿主事实。若动态任务受阻或运行中断，应说明为什么结论为未决，而不是将其视为阴性。列出项目既有发现（沿用）：来源运行、首次发现时间、项目 revision、验证状态，并注明它们不计入本次新发现。只有独立真值集和相同任务条件下才讨论覆盖率或对比指标。

## 6. 导出与自动验证记录

列出 Markdown、JSON 和证据包，说明如何回放任务配置、冻结项目图、Planner 版本、动态任务与尝试、工具轨迹、证据引用、项目台账与自动验证记录。报告顶部的结论摘要、结论与限制由 Planner 生成，明确标注它只总结已列出的证据与验证结果，不构成新发现；宿主负责统计、任务图与证据章节。界面可展开查看 Planner/worker/POC Agent 的工具调用与“依据摘要”；不得将该摘要表述为或替代模型隐藏思维链。POC 由隔离的 `poc-runner` 在本地 Lab30 中执行，证据包记录目标、版本、登录会员、正常输入、测试输入、实际观测、runner manifest（job id、退出码、产物哈希）与附件；上传源码本身从不执行。
