# PHP 源码目标审计报告目录

默认导出面向任意上传 PHP 源码的目标审计，不把项目假定为 DVWA，也不把所有结论强行归入 SQL 注入、XSS 或命令注入。固定漏洞实验的旧报告仍可按其历史格式复现；新目标任务按下面目录输出。

## 1. 任务概述与边界

记录源码快照名称与哈希、冻结范围、任务目标、验收条件、模型、预算、每个动态任务的最大尝试、任务总尝试上限、Planner 回合上限、worker 上限、POC 策略和最终状态。说明“不可达”只针对已冻结范围和已经由 Planner 穷尽的证据方向，不是对整个系统的绝对安全声明。

## 2. 执行方法与可追溯性

说明 ZIP 不可变快照、PHP 语法索引、冻结项目图（文件、符号、静态 include、调用点、模块聚合、高置信入口候选与未解析静态根）、三个只读工具、范围访问策略、预算和证据引用校验。解释 `top_level` 只是语法分片而非入口事实，高置信入口与未解析根都只用于 Planner 导航。项目图只用于 Planner 规划，不能作为发现证据。说明事件先写 SQLite 再通过 SSE 推送；工具调用和结果通过 `call_id` 配对。

模型提供的内容称为“审计依据摘要”或“决策依据”：它应陈述当前结论、已经读取的源码事实、引用和不确定项。不要记录或展示模型隐藏思维链、供应商 thinking delta、完整提示词或密钥。

## 3. Planner 任务图与多 worker 执行

展示主 Planner、项目图、持久化任务图和 worker 的关系。记录每个 Planner 回合的项目图/worker 依据摘要、任务创建与更新、依赖关系和下一步；记录每个动态任务的状态、认领 worker、尝试、初始多文件上下文、依赖摘要交接、可检索的受限同行工具轨迹、用量、错误和终止原因。同行轨迹只能作为线索，不能替代当前 worker 的源码证据。解释 `achieved`、`continue`、`no_evidence`、`blocked` 的差异，以及 `completed`、`unreachable`、`inconclusive`、`cancelled`、`interrupted` 的收束条件。

## 4. 审计结果与源码证据

每条结果至少包含标题、类型、摘要和通过校验的原始行号。可选地记录风险等级、相关输入、数据/控制流、敏感操作、边界/防护、前置条件、POC 和修复建议。源码事实、路由清单、认证边界、配置来源、数据流和漏洞都使用同一通用结果模型；缺失字段不应以模板占位文本伪造。

## 5. 结论限制与后续动作

记录动态 include、运行时配置、跨服务调用、项目图的静态边界、模型/网络失败、共享尝试或 Planner 回合耗尽，以及 POC 验证或源码人工复核差异。若动态任务受阻或运行中断，应说明为什么结论为未决，而不是将其视为阴性。只有独立真值集和相同任务条件下才讨论覆盖率或对比指标。

## 6. 导出与人工复核

列出 Markdown、JSON 和证据包，说明如何回放任务配置、冻结项目图、Planner 版本、动态任务与尝试、工具轨迹、证据引用和人工复核记录。界面可展开查看 Planner/worker 工具调用与“依据摘要”；不得将该摘要表述为或替代模型隐藏思维链。对需要验证的 POC，记录授权环境、版本、正常输入、测试输入、实际观测和附件；系统不执行上传源码或 POC。
