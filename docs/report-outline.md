# 实验报告固定目录

以下六章标题来自项目根目录的《网络安全》大实验：基于LLM辅助的漏洞挖掘设计与验证+.docx 中“六、报告固定目录”。导出报告应按此顺序组织；没有完成的实验以“待实测”标注，不填充推测指标。

## 1. 实验概述（目的、背景、实验边界）

说明单用户本地 PHP 白盒审计、固定三类漏洞模式与可配置目标任务模式、人工验证的目标；记录项目来源、快照哈希和范围。目标任务要同时记录目标、验收条件、每项最大轮次、任务总尝试上限、worker 上限与是否要求 POC。DVWA 六样本用于检验实验流程，不能据此推断未知项目检测能力。

## 2. 传统漏洞挖掘与 LLM 辅助漏洞挖掘技术对比

对比源码阅读、传统工具与 LLM 辅助阅读的输入、输出、适用条件及人工工作。模型候选与人工结论分开描述；未执行传统扫描时不要填写对比实测数据。

## 3. 系统总体架构（架构图 + 数据流向）

```mermaid
flowchart LR
    A[代码预处理模块] --> B[LLM 提示词工程模块]
    B --> C{运行模式}
    C -->|固定三类| D[单元审计执行器]
    C -->|目标任务| E[目标协调器与共享工作队列]
    E --> F[并发源码 worker]
    F --> E
    D --> G[POC 验证实操模块]
    E --> G
    G --> H[结果校验降噪与复盘优化模块]
    H --> B
```

说明 ZIP 不可变快照、语法索引、固定审计队列、目标与工作项队列、三个只读工具、持久化事件、证据引用校验与人工验证记录之间的数据关系。固定模式由后台运行循环串行消费；目标任务在单次运行内由多个 worker 原子领取共享工作项。注明 `achieved` 发现、工作项结算、目标达成和未领取工作项跳过在同一事务中提交，以及重启/取消如何收束运行中的工作。

## 4. 模块详细设计

必须覆盖五个模块的设计依据、操作方法、输入与输出：

1. 代码预处理：来源、原始行号、文件哈希、排除范围、清洗和切片规则及其遗漏记录。
2. Prompt 提示词工程：四段式全文、三类漏洞规则、反幻觉证据约束、P0/P1/P2 改动原因和关联问题。
3. LLM 漏洞推理：语法结构、漏洞语义、实际风险；预算、依赖补读、候选与缺失上下文的处理。目标任务使用独立受控执行指令，不复用固定三类漏洞 Prompt；还要说明目标/验收条件如何冻结、worker 如何原子领取工作项、`continue` 如何带着下一关注点重试、每轮记录如何保留，以及何时由协调器判定 `met`、`unreachable` 或 `inconclusive`。
4. POC 实操：原始脚本、适配脚本、运行环境、正常输入对照、攻击输入结果、日志或截图、执行状态和人工结论。
5. 结果校验与复盘：人工裁决、去重、覆盖率、误漏报归因、相同配置的两轮迭代比较及可复算统计。

## 5. 方案缺陷与优化方向

记录上下文不足、切片边界、动态 PHP 解析限制、模型输出不稳定、POC 环境差异等实际遇到的问题，并关联具体单元、事件或验证记录。目标任务须区分“所有工作项正常完成、探索轮次或任务总尝试上限耗尽且没有受阻项”的 `unreachable`、源码/环境缺失及模型/超时/预算/结构化输出失败重试耗尽（包括被总上限截断的待重试项）造成的 `inconclusive`，以及取消/服务中断；它们不作为阴性结论。普通上传项目的 Recall、FN、TN 写“无法计算”；自定义目标任务不套用固定三类漏洞真值矩阵；只有独立核验的同类真值子集才能计算完整混淆矩阵。
