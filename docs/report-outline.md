# 实验报告固定目录

以下六章标题来自项目根目录的《网络安全》大实验：基于LLM辅助的漏洞挖掘设计与验证+.docx 中“六、报告固定目录”。导出报告应按此顺序组织；没有完成的实验以“待实测”标注，不填充推测指标。

## 1. 实验概述（目的、背景、实验边界）

说明单用户本地 PHP 白盒审计、三类漏洞、人工验证的目标；记录项目来源、快照哈希和范围。DVWA 六样本用于检验实验流程，不能据此推断未知项目检测能力。

## 2. 传统漏洞挖掘与 LLM 辅助漏洞挖掘技术对比

对比源码阅读、传统工具与 LLM 辅助阅读的输入、输出、适用条件及人工工作。模型候选与人工结论分开描述；未执行传统扫描时不要填写对比实测数据。

## 3. 系统总体架构（架构图 + 数据流向）

```mermaid
flowchart LR
    A[代码预处理模块] --> B[LLM 提示词工程模块]
    B --> C[LLM 漏洞推理挖掘模块]
    C --> D[POC 验证实操模块]
    D --> E[结果校验降噪与复盘优化模块]
    E --> B
```

说明 ZIP 不可变快照、语法索引、固定审计队列、三个只读工具、持久化事件、证据引用校验与人工验证记录之间的数据关系。注明队列冻结和后台单 worker 的执行边界。

## 4. 模块详细设计

必须覆盖五个模块的设计依据、操作方法、输入与输出：

1. 代码预处理：来源、原始行号、文件哈希、排除范围、清洗和切片规则及其遗漏记录。
2. Prompt 提示词工程：四段式全文、三类漏洞规则、反幻觉证据约束、P0/P1/P2 改动原因和关联问题。
3. LLM 漏洞推理：语法结构、漏洞语义、实际风险；预算、依赖补读、候选与缺失上下文的处理。
4. POC 实操：原始脚本、适配脚本、运行环境、正常输入对照、攻击输入结果、日志或截图、执行状态和人工结论。
5. 结果校验与复盘：人工裁决、去重、覆盖率、误漏报归因、相同配置的两轮迭代比较及可复算统计。

## 5. 方案缺陷与优化方向

记录上下文不足、切片边界、动态 PHP 解析限制、模型输出不稳定、POC 环境差异等实际遇到的问题，并关联具体单元、事件或验证记录。失败、未决样本单列，不作为阴性结果。普通上传项目的 Recall、FN、TN 写“无法计算”；只有独立核验的真值子集才能计算完整混淆矩阵。

## 6. 实验总结

以可追溯的运行和人工验证结果说明实际完成内容、两轮优化的实测提升或退化、未完成环节及后续验证方向。列出 Markdown、JSON 和证据包文件，保证统计能由导出数据复算。
