# Worker 重复 finding 与增量提交

日期：2026-11-09 至 2026-11-10。对应 `finding-reuse-v1`，适用于 `discovery_first` 且使用 `bounded-v1` 调查合同的任务，包括现有复测和继续审计。实现独立编写，没有引入额外运行依赖或新的 LLM 去重调用。

## 实际问题

只读核对最近记录：父运行 `588ca76c3b0045e5b1769f32e52ebc40` 有 23 条原始 finding，其中 11 条已标记 duplicate；当前继续任务 `f1f9fa946dc350c7a611d90e67b5b463` 有 31 条，其中 22 条已标记 duplicate。二阶查询、会员查询、目录查询的同一根因坐标分别被重报 8～11 次、6～9 次、6～8 次。

已有去重发生在落库和报告聚合阶段，此时 worker 已经生成完整的描述、评分、POC 和修复内容。初始 worker 记忆又按任务的入口文件筛选：从 helper、测试或其它调用者沿依赖找到已知 sink 时，相关已知结论可能没有进入上下文。已有接口要求 `achieved` 必须携带完整 finding，单纯补核已有漏洞也容易再次生成整份报告。

因此，优化点应放到完整报告生成之前，同时保留后续独立审查和原始历史。

这些做法不等于自动合并所有同坐标漏洞。不同输入、危险操作、必要前提需要保留；评分或标题变化本身不应要求再生成一份完整报告。

## 现在的链路

1. **开工提供短索引。** 运行全局索引保留规范 finding ID、revision、根因分类、主定位与验证状态，不受初始任务路径过滤。正文、CVSS 和 POC 不进入全局索引。局部相关记忆只保留当前有效主张，预算从 32 KiB 收窄到 8 KiB。分页明确给出 `next_offset`，省略不表示不存在。
2. **沿依赖时可查最新记录。** `lookup_findings(path, line, vulnerability_type, offset, limit)` 返回最新已提交结论的短信息，按需附带输入、操作和前提；相同查询不会命中旧的只读缓存。正式 JSON 发布前再次刷新索引，验证时也重新读取宿主状态。
3. **重复只交引用。** `achieved` 可只含 `finding_references`：`finding_id`、`revision`、实际读取的证据区间和简短理由。无需重写标题、完整数据流、CVSS、POC、修复或复测说明。旧的单数 `finding` 仍可解析，但从实际发布 schema 中移除，避免同时输出 `finding` 和 `findings[0]`。
4. **独立漏洞说明差异。** 对已有同分类、同主定位的结论，完整 finding 须有 `related_finding_id` 和具体 `novelty_reason`；同一提交中反复使用同一根因坐标也须说明差异。宿主不自动判定这些差异成立：该主张保留为独立待审项，避免先被模糊台账匹配或运行内相似度合并吞掉。完全相同的数组项仅在没有索引引用时去重，已有 `finding_index` 不被悄悄改号。
5. **引用必须真实且留痕。** 发布及提交事务分别检查当前运行、版本、有效状态和本次读取区间；证据必须覆盖原根因，可附带已读的来源链。撤回项、重复别名、动态反证项和旧版本不能作为有效引用。引用不能被改写成 `no_evidence`，也不会变成新的动态验证或终审接受。
6. **候选和终审接得上。** 已核实为既有漏洞的本地候选可通过 `candidate_updates.finding_id` 关联本次验证过的短引用；其它 pending 候选继续保留。佐证持久化到 task attempt，终审批次携带引用、理由和对应原始源码；相同源码窗口只提供一次，正文仍使用宿主管理的分页。继续任务会重绑复制后的 finding ID。

原始 finding、attempt、冻结报告不会被清理或重写。已标记 duplicate 的历史仍保留。当前仍在同时生成的多个 worker 可能各输出一份完整报告；现有落库去重继续处理这种竞争，不为降低数字放松证据或偷偷删除候选。

## 验证与开销口径

对已标记 duplicate 的记录做结构化载荷投影：父运行的 11 份完整 finding JSON 共 34602 字节，同身份短引用约 4128 字节；当前任务的 22 份完整载荷共 61177 字节，短引用约 7862 字节，重复报告载荷分别减少约 88.1%／87.2%。这是 UTF-8 字节估算，不能当作实际 token 或账单降幅。

以当前任务全部记录做同一输入对照，原相关记忆 17745 字节；有效主张的局部记忆加全局索引共 8039 字节，约减少 54.7%。真实任务的局部路径选择和新增发现会改变这个比例。

[隔离验证记录](validation/finding-reuse-isolated-2026-11-09.json)包含只读统计及真实模型窄复核；[全量测试记录](validation/finding-reuse-tests-2026-11-09.json)包含提交、版本竞争、同位置独立漏洞、候选保留与继续任务引用重绑的回归。验证使用临时 SQLite 副本；只执行指定的来源核实，未完成其它复制任务，也未宣告整个审计完成，未启动新 POC。

最终真实模型窄复核使用 **2 次请求、0 次工具、约 11.5 秒、1944 输出 token**，提交 4 条短引用、0 条新 finding，经过真实提交事务并出现在终审输入中。第一次把重复的权限／来源观察附到旧根因时，被根因引用校验拒绝；第二次依据短引用纠正样板成功。宿主没有自动删除观察或放宽证据要求。该样本只验证新协议可落库，不代表全量运行已经获得固定比例的实际 token 节省。
