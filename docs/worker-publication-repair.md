# Worker 发布与全量审计恢复修复

## 问题与边界

2026 年 10 月 27 日运行 `57df26c83d6d4f27b9c91a183dc04efa` 已保存 11 条有效的静态漏洞候选，
并非没有产出。该运行约 529 秒结束，预算为 1800 秒，读取 40/69 个源码文件。
Planner 已成功派发任务；本轮的主要失败发生在一个 Worker 的最终结果发布及后续阻塞判断。

该 Worker 多次达到 4096 token 输出上限，随后继续用 Python 变量组装、打印中间结果，
一直没有提交完整结论。成功执行中间代码会重置动作纠错计数，最终历史上下文达到 192KiB。
这个宿主执行限制被作为持久阻塞处理。其他任务后来保存了新发现，但相同阻塞指纹仍触发停止，
尚未使用完预算便结束。原运行同时使用“至少一处漏洞”的目标收束政策，不适合作为全量审计的默认入口。

11 条是静态候选数量，不能等同于自动 POC 验证通过数量或官方真值命中数。
本修复不重算历史运行、不修改旧发现和评分，不执行真实模型请求、不重置 Lab30。

## 执行及发布

- 源码探索继续使用 CodeAgent，默认最多 6 次请求，并从同一工作项请求额度内预留最终发布及纠错额度。
- 最终 `task_publish` 使用受宿主校验的 `GoalAssessment` JSON，不执行模型生成的 Python，也不开放工具。
  默认最多 3 次发布请求，仍受工作项剩余请求、时间、历史容量及全局截止约束；取消后拒绝迟到结果。
- 发布请求只携带已实际展示的源码、读取范围与任务上下文，不重放整段 CodeAgent 动作历史。
  保留原始行号证据门禁，不以同行线索、导航结果代替源码。
- 每批最多 2 条完整发现；具体未完成方向写入 `remaining_work`。
  当前小批先保存，剩余方向在同一任务的剩余尝试额度内继续。达到任务上限仍未完成时明确阻塞，交由 Planner 缩小或重开。
- 使用漏洞类型和主定位生成稳定存储槽，避免后一批覆盖前一批。相同定位继续记录修订；没有新合同标记的旧结果保持兼容。
- `context_limit`、无效输出及传输失败属于执行失败，不是源码缺失，也不能证明当前方向没有漏洞。
  它们在现有任务尝试上限内恢复，不增加总预算。

## 阻塞恢复与证据质量

重复阻塞改为同时比较已落库的实际进展：任务尝试、结论版本、验证变化及合并后的源码读取范围。
有真实进展时允许继续规划；仅更换任务名称、时间、ID 或重复读取不算进展。
原阻塞任务仍需显式处理，无进展时保持有界停止，不能把新增任务当作旧方向已完成。

新执行的普通 Worker 与实验 Worker 均须明确提交 `vulnerability_type` 与 `primary_location`。
主定位必须在本条发现已读且引用的源码范围内；错拼类型会被拒绝。
确实无法归类时允许 `unknown`/`other`，但必须提供具体的分类困难说明，不能由宿主根据标题猜测类型。
CVSS 仍由原有引擎计算，POC 的身份、对照、成功作业引用及浏览器证据要求保持原规则。

## 新建全量审计

新建页面默认“全量覆盖复核”，明确设置 `completion_policy=coverage_review`、`stop_on_achieved=false`。
发现一条漏洞后继续处理可执行方向；结束前检查覆盖缺口。达到预算仍停止并保存已有成果，不承诺读完每行。
快速目标审计保留为显式选项；旧 API 未提供模式时继续使用原有 `goal` 行为。
冻结实验显式提供的验收条件保持原样。

默认 `baseline_policy=fresh`：本轮从空白漏洞基线独立取证，Planner 与 Worker 不接收项目历史结论，
旧的已验证漏洞不能代替本轮发现完成目标，也不能作为沿用成果混入本轮报告。
历史项目台账、运行和证据保留，新发现继续按源码项目关联。
选择继承台账时恢复已有线索的审计方式；旧运行缺省仍为 `inherit`。

## 离线验收与使用

新增或扩展的回归集中在：

- `backend/tests/test_worker_publication_recovery.py`：截断和错误字段恢复、三次发布上限、拒绝中间 Python、
  容量失败分类、严格类型及主定位、分批保留剩余方向、共用请求预算。
- `backend/tests/test_blocker_progress_recovery.py`：真实进展与无进展、分批持久化、同定位修订及剩余方向结算。
- `backend/tests/test_worker_finding_contract.py`：分类合同、未知类型说明及持久化防御校验。
- `backend/tests/test_full_audit_creation.py`：模式冻结、实验条件兼容、空白基线及历史成果隔离。
- `frontend/tests/taskDraft.test.mjs` 与 `scripts/ui_sources_smoke.py`：模式切换、历史任务恢复、提交字段与响应式布局。

全部模拟使用脚本模型与临时数据，不调用真实模型或改动当前靶场。完整回归结果在交付时记录。
应用改动需要重启后端，并加载重新构建的前端；然后创建新的全量审计。
旧的失败运行保留原状态，不会自动补跑或转成成功。
