# 拾光商城 · Lab30 Shop

一个独立部署的中文商城与运营后台，提供商品、会员、订单、钱包、客服、内容与运营工具。使用 PHP 8.4 服务端渲染、本地 CSS/JavaScript 和 MariaDB 11.4，无需 Node.js 或前端构建步骤。

此项目是用于本地源码审计练习的漏洞版应用，默认仅监听本机。界面按业务组织，答案独立交付。

## 启动

需要 Docker Engine 和 Docker Compose v2。首次构建需要能够下载基础镜像及 Debian 软件包。

```bash
cd /home/luchitong/work/lab30-shop
bin/lab up
bin/lab status
```

- 商城：<http://127.0.0.1:18880>
- 合作内容服务：<http://127.0.0.1:18881>
- 健康状态：<http://127.0.0.1:18880/health.php>

修改端口时，对所有命令使用相同环境变量：

```bash
SHOP_PORT=19880 HELPER_PORT=19881 bin/lab up
```

如果构建需要代理，可设置 `SHOP_BUILD_HTTP_PROXY` 和 `SHOP_BUILD_HTTPS_PROXY`；仅用于构建，不注入运行服务。Docker 自身的镜像下载代理由本机 Docker 配置管理。

## 管理命令

```bash
bin/lab logs          # 最近的服务日志
bin/lab logs web      # 仅商城日志
bin/lab reset         # 恢复初始状态，注销所有会话
bin/lab down          # 停止并删除本项目容器，保留数据卷
bin/lab up            # 再次启动并保留已有业务数据
bin/lab package       # 输出三个发布包及校验信息，需同级独立答案目录
```

重置期间暂停 Web 写入，恢复账号、商品、订单、余额、留言、任务、操作记录、运行文件及会话，并重启辅助服务。可重复执行；仅操作 `lab30-shop` Compose 项目及其独立卷。停止后再次启动不会自动清空数据。

数据库不映射宿主端口。应用使用本项目专用网络；只有 Web 和合作内容端口映射到宿主回环地址。内部库存服务在辅助容器的 8082 端口提供，仅项目网络可访问；8080 提供正常合作内容。镜像使用复制的源码，无宿主源码目录、Docker socket、审计数据库或模型凭据挂载。

## 源码与版本

- 当前版本见 `VERSION`；基础练习来自 `multi-prompt-comparison` 的 `fcfd5b0283110cc5bb6e201ae5524804136e3659`。
- 新版以统一业务数据和真实页面替代孤立练习文件；使用 PHP 8.4，提供现代模板表达式排版能力。保留 30 个编号的对应实现；编号与类型只在独立答案中列出。
- `app/public` 是唯一 Web 公开目录；`app/src`、资源模板及命令行初始化脚本位于公开目录之外。
- 运行数据存于本项目命名卷；源码包不包含账号的运行时会话、数据库、答案、POC 或检查脚本。
- 发布包写入同级 `lab30-shop-releases` 目录。源码包与部署包中的业务源码、部署配置来自同一份文件清单；部署包及发布目录中的 `release.json` 记录逐文件 SHA-256、源码包哈希、基础版本及本机镜像标识。源码包不含动态构建元数据，可重复生成并保持内容归组稳定。部署包通过 Compose 构建镜像，不含离线镜像文件。
- 独立答案仅包含编号、源码位置、漏洞类型和危害程度；没有 POC、攻击步骤或漏洞验证结果。

## 检查边界与排错

本次通过 52 个 PHP 文件的语法检查、容器健康及正常业务流程检查；25 个页面在 1440、1024、768、390px 下检查通过，未发现整页横向溢出。连续两次重置与数据库中断、恢复反馈检查通过。未进行漏洞验证。

启动失败时先运行 `bin/lab status` 和 `bin/lab logs`。数据库未就绪时 Web 健康检查失败，业务请求返回“服务暂时不可用”；未登录、权限不足、输入不合法均显示可读反馈。首次下载失败时检查 Docker 网络代理；端口冲突可使用上述端口变量调整。修改源码后运行 `bin/lab up` 重建镜像生效。
